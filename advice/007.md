## 一、`rx_cap_tokens` 的实现机制成立，但“hard budget”表述需要修

代码现在是：先产生物理 Bernoulli offers；若 receiver 过载，则随机无放回保留

[
m_i=\lfloor c_i\rfloor
]

个，并以

[
\theta_i=c_i-m_i
]

的概率再收一个。

所以真正满足的是

[
N_{i,t}^{adm}\le \lceil c_i\rceil
]

而不是严格的

[
b_{\rm tok}N_{i,t}^{adm}\le B_i^{rx}.
]

当

[
c_i=\frac{B_i^{rx}}{b_{\rm tok}}\notin\mathbb Z
]

且多收第 (m_i+1) 个 token 时，

[
(m_i+1)b_{\rm tok}>B_i^{rx}.
]

因此目前准确名称应是：

> **randomized per-cycle token admission cap**

而不是严格的：

> **hard per-cycle bit budget**。

另外，

[
E[N^{adm}]=c_i
]

也只在 receiver **已经过载、offer 数大于 (m_i)** 时成立；若 offer 数本来只有 (n_i\le m_i)，显然

[
E[N^{adm}\mid n_i]=n_i<c_i.
]

所以文档里最好写成：

[
E[N^{adm}\mid N^{offer}>m_i]=c_i.
]

### 两种处理办法

如果你真正要研究 **hard budget boundary**，我更推荐：

[
N^{adm}*{i,t}
\le
\left\lfloor\frac{B_i^{rx}}{b*{\rm tok}}\right\rfloor.
]

直接 floor-only。

如果又想保留非整数平均容量，则用 **credit/carry-over budget**，不要靠当周期“借”一个 token：

# [ C_i(t+1)

## C_i(t)+B_i^{rx}

b_{\rm tok}N_{i,t}^{adm},
]

并且不允许累计 credit 变负。

这样既能保持长期平均预算，又真正满足 cumulative physical budget。

for scenario_seed in scenario_seeds:

        q_targets=Q_MAX,
    )

然后同一个 `full` 里面做所有 Q/rho sweep。

# 四、当前 Hoeffding UCB 有一个实质统计 bug

这一点必须在正式结果前修。

现在：

```python
ucb_fa = hoeffding_ucb(round(p_fa*n_runs), n_runs)
ucb_md = hoeffding_ucb(round(p_md*n_runs), n_runs)
```

但：

[
P_{FA}
]

实际上是在：

[
H=0
]

的 samples 上估计，

而：

[
P_{MD}
]

是在：

[
H=1
]

samples 上估计。

如果 prior 是 0.5，那么大致：

[
n_0\approx n/2,\qquad n_1\approx n/2.
]

当前却两个都用 (n)。

于是置信区间被人为缩窄。

Hoeffding radius：

# [ \epsilon(n)

\sqrt{
\frac{\log(1/\delta)}
{2n}
}.
]

正确应该分别：

# [ \epsilon_{FA}

\sqrt{
\frac{\log(1/\delta)}
{2n_0}
},
]

# [ \epsilon_{MD}

\sqrt{
\frac{\log(1/\delta)}
{2n_1}
}.
]

若 (n_0\simeq n/2)，当前 UCB 大约乐观了：

[
\sqrt{2}.
]

### 所以 `simulate_frids_v2` 最好直接返回

每个 target 的：

[
N_{H0,q},\quad N_{FA,q},
]

[
N_{H1,q},\quad N_{MD,q}.
]

不要先变成小数概率，再：

```python
round(p*n)
```

重构 count。

# 五、还有一个 simultaneous confidence 问题

当前每一个 target、每一个 error 都使用：

[
\delta=0.05.
]

但 Gate 要求：

[
P_{FA,q}\le\alpha,\quad
P_{MD,q}\le\beta,
\quad
\forall q.
]

也就是说总共有：

[
2Q
]

个约束。

Q=64 时就是：

[
128
]

个 simultaneous inequalities。

所以：

> 每个 inequality 95% UCB

不等于：

> 所有 128 个 inequality 同时 95% 成立。

最简单处理是 Bonferroni：

# [ \boxed{ \delta_{\rm each}

\frac{\delta_{\rm cell}}{2Q}
}
]

比如：

[
\delta_{\rm cell}=0.05.
]

这样才可以说：

> with at least 95% confidence, all target-wise FA/MD constraints hold simultaneously.

如果嫌 Hoeffding 太保守，可以以后换 Clopper–Pearson / Wilson / empirical Bernstein；但现在先把数学口径做对。

# 六、PASS / FAIL / UNCERTAIN 也建议完全置信区间化

当前 PASS 用 UCB，但 FAIL 是：

```python
p > target + 0.02
```

这样的点估计 margin。

更干净的是同时计算：

[
LCB_{q},UCB_q.
]

然后：

### PASS

所有：

[
UCB(P_{FA,q})\le\alpha
]

且：

[
UCB(P_{MD,q})\le\beta.
]

### FAIL

只要存在一个 q：

[
LCB(P_{FA,q})>\alpha
]

或：

[
LCB(P_{MD,q})>\beta.
]

### UNCERTAIN

剩下所有情况。

这样：

[
\boxed{
PASS / FAIL / UNCERTAIN
}
]

完全由 statistical certificate 定义，不再需要人为 `+0.01/+0.02`。

这会让论文里的 phase boundary 干净很多。

# 七、`rho_I^{eff}` 当前也还没有完全匹配 hard admission 机制

当前 communication axis 运行的是真实：

[
\text{Bernoulli physical offers}
\rightarrow
\text{receiver admission}.
]

但 `rho_I_eff` 是通过 `_apply_drop()` 的 deterministic survival approximation 得到的，而不是从实际 admission process 统计出来的。

这里有潜在偏差。

原因是 admission probability 不是简单：

[
\frac{c_i}{K-1}
]

因为实际 offer 数：

[
N_i^{offer}
]

本身受每条物理 U2U Bernoulli success 影响。

对于某一已 offer packet，其 admission probability 应该类似：

# [ P(\text{admit}\mid\text{offered})

E\left[
\min\left(
1,
\frac{M_i}{N_i^{offer}}
\right)
\middle|
\text{packet offered}
\right],
]

而不是简单用固定：

[
\frac{M_i}{K-1}.
]

因此正式 `rho_I_eff` 最稳妥的方式是：

### 直接统计 effective delivery

在 simulator 里累计：

[
N_{ij}^{offer},
\qquad
N_{ij}^{admit},
]

定义：

# [ \hat s_{ij}^{eff}

\frac{N_{ij}^{admit}}
{N_{ij}^{attempt}}
]

或分成：

[
s_{ij}^{phy}
\times
s_{ij}^{adm|offer}.
]

再用这个构造：

[
g_{iq}^{eff}
]

和：

[
\rho_I^{eff}.
]

这样：

[
\rho_I^{pre}
]

和

[
\rho_I^{eff}
]

才真正对应同一个 stochastic system。

# 八、Info axis 目前基本可用，但注释和统计目标要分清

Info axis 确实：

```python

```

所以 scenario seed 真变化了。

但当前每一个 `geom` 都形成单独 cell，然后在这个 geometry 内跑若干 MC seeds。

因此代码注释写：

> “per-target point estimate pools across geoms”

并不准确。

实际上是：

[
\boxed{
\text{within-scenario MC aggregation}
}
]

我反而建议保持这个做法。

不要把不同 geometry 的 Bernoulli trials直接当 iid 样本池。

更有学术意义的是：

1. 每个 scenario 得到独立 PASS/FAIL/UNCERTAIN；
2. 一个 physical phase point 再统计：

[
P_{\rm scenario}(\text{PASS}),
]

比如：

- robust feasible：5/5 PASS；
- mostly feasible：≥4/5；
- mixed：2–3/5；
- mostly infeasible：≤1/5。

这样可以同时表达：

[
\text{MC uncertainty}
]

和：

[
\text{scenario heterogeneity}.
]
