## 一、当前系统真正需要的不是“再优化一个算法”，而是统一目标

目前几层实际上已经自然形成了一条很好的理论链：

[
\boxed{
\text{局部证据}
\rightarrow
P_D\text{-optimal fusion}
\rightarrow
\mathbb E[P_D]\text{-based selection}
\rightarrow
\text{resource allocation}
\rightarrow
\text{congestion-aware fair scheduling}
}
]

问题在于，代码层还没有完全按这条链统一。

G3 已经说明：**deflection 不是始终可靠的任务效用代理**。平均 (P_D) 差异只有 (0.0051)，并不算巨大，但更重要的是：

[
0/468
\quad\text{vs}\quad
80/468
]

的单调性差异。

因此 G3 真正的意义不是“平均提高 0.5 个百分点”，而是：

> 在固定 NP 检测语义下，直接优化 detection probability 可以避免 surrogate objective 引入的非单调协作行为。

这比单纯报平均增益要强得多。

G4 又进一步表明，expected-(P_D) 选择在当前实验分布中几乎与 exact oracle 重合。因此下一步 **G5 和 CA-FRIDS 都不应该再重新发明一套 deflection/density/QoS utility**，而应统一到：

# [ F_q(S)

\mathbb E
\left[
P_{D,q}
\mid S,,
P_{FA,q}\le \alpha_q
\right].
]

然后每个动作 (a) 的价值定义成真正的边际任务收益：

# [ \Delta_q(a\mid S)

F_q(S\cup{a})-F_q(S).
]

这一步是当前最关键的模型精炼。

# 二、建议把 CA-FRIDS 正式升级为一个“在线 max-min 公平优化”算法

当前 `ca_frids.py` 已经有一个非常好的理论雏形：目标权重采用类似乘法更新/simplex 权重，而且拥塞时基于资源收益进行 admission。

这其实不应该再叫“若干 congestion-aware heuristic 的组合”，而应该正式写成：

[
\boxed{
\max_{\pi}
\min_{q\in\mathcal Q}
\liminf_{T\rightarrow\infty}
\frac1T
\sum_{t=1}^{T}
\mathbb E_\pi[r_{q,t}]
}
]

subject to

[
\sum_{a\in A_{o,t}}c_a
\le C_{o,t},
\qquad
\forall o,t .
]

其中

# [ r_{q,t}

F_q(S_t)-F_q(S_{t-1})
]

或者根据你的实验定义采用一轮累计 expected-(P_D)。

利用

# [ \min_q r_q

\min_{\mathbf y\in\Delta_Q}
\sum_q y_qr_q ,
]

就得到一个在线 saddle-point 形式：

[
\max_{\pi}
\min_{\mathbf y\in\Delta_Q}
\mathbb E
\left[
\sum_q y_q r_q
\right].
]

当前代码中的乘法更新可以自然解释为 entropic mirror descent / multiplicative weights：

# [ y_{q,t+1}

\frac{
y_{q,t}\exp(-\eta r_{q,t})
}{
\sum_jy_{j,t}\exp(-\eta r_{j,t})
}.
]

因为低收益目标的指数衰减较慢，它会得到越来越大的相对权重，所以系统自动把资源推向长期弱目标。

这不是为了“包装算法”。乘法权重本来就是在线优化、零和博弈和对偶优化中非常成熟的工具。([计算理论](https://theoryofcomputing.org/articles/v008a006/?utm_source=chatgpt.com))

在奖励归一化到 ([0,1])、资源 oracle 每轮误差为 (\epsilon_t) 等标准条件下，可以进一步争取得到类似

## [ \min_q \frac1T\sum_{t=1}^{T}r_{q,t} \ge V^\star

## O\left( \sqrt{\frac{\log Q}{T}} \right)

\frac1T\sum_t\epsilon_t .
]

这个定理一旦做出来，CA-FRIDS 的论文级别会比现在高很多：

**现在：**
“一个拥塞条件下效果较好的调度器”。

**升级以后：**
“一个具有在线公平 regret / optimality-gap 保证的 task-oriented congestion-aware scheduling framework”。

# 三、当前 CA-FRIDS 的资源选择还值得再改一层

建议把当前类似

[
\frac{\text{benefit}-\text{comm cost}}
{\text{slot cost}}
]

的 density admission 改成统一的 primal-dual score：

# [ \boxed{ s_a(t)

## \sum_q y_{q,t}\Delta_q(a\mid S_t)

## \lambda_B b_a

\sum_o\nu_{o,t}c_{ao}
}
]

其中：

- (y_q)：目标公平价格；
- (\lambda_B)：通信 bit/airtime 成本；
- (\nu_o)：接收器/owner 拥塞价格；
- (\Delta_q)：G3/G4 延伸下来的 expected-(P_D) 边际收益。

容量价格更新：

# [ \nu_{o,t+1}

\left[
\nu_{o,t}
+
\rho
\left(
\sum_a c_{ao}x_{a,t}
-C_o
\right)
\right]_+ .
]

这样以后系统只有两类价格：

[
\underbrace{y_q}*{\text{弱目标需要资源}}
\qquad+\qquad
\underbrace{\nu_o}*{\text{拥塞资源太昂贵}}.
]

这比继续增加 congestion factor、penalty factor、threshold factor 更容易分析，也更有通信意义。

而且它天然支持分布式化：

[
\text{owner广播 }\nu_o
\rightarrow
\text{UAV局部计算 score}
\rightarrow
\text{局部 offer/admission}.
]

不需要把完整全局 CSI 或全部候选表通过总线发送。

# 四、G4 的 (1-1/e) 结论现在要特别谨慎

这里我建议你专门做一次理论纠偏。

经典结论是：对于**单调子模函数 + cardinality constraint**

[
|S|\le K,
]

普通 greedy 可以得到

[
1-\frac1e
]

近似。Nemhauser–Wolsey–Fisher 的经典分析就是这一类。([SciSpace](https://scispace.com/papers/an-analysis-of-approximations-for-maximizing-submodular-set-1c63km7c1y?utm_source=chatgpt.com))

但是如果你的 G4 已经涉及：

[
\sum_{i\in S}c_i\le B
]

且 (c_i) 不相同，那么这是 **knapsack constraint**。

此时不能简单地写：

> “因为单调子模，所以 density greedy 有 (1-1/e) 保证。”

Sviridenko 的 (1-1/e) knapsack 结果使用了额外的枚举和 greedy completion，并不是普通 density-greedy 自动拥有这个保证。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0167637703000622?utm_source=chatgpt.com))

因此你的 fresh 结果：

[
\text{mean/min approximation ratio}=1.0
]

以及

[
100%\ge1-1/e
]

现在最好表述为：

> **empirical approximation certificate on the tested instances**

除非你已经严格证明当前约束属于 cardinality special case。

甚至我建议进一步利用这个异常漂亮的 `ratio=1.0`：

**不要急着满足于 (1-1/e)。**

对小规模实例 exhaustive search：

[
Q=2,3,\quad N=3,\ldots,8,
]

随机扫描：

- heterogeneous (P_D)；
- heterogeneous costs；
- highly correlated reports；
- weak-target regime；
- tight budgets。

目的就是主动寻找

[
S_{\rm greedy}\ne S_{\rm exact}
]

的最小 counterexample。

如果大量搜索仍找不到，那么很可能你的 expected-(P_D) 函数存在比一般子模性更强的结构；如果找到，则论文老老实实保留 generic approximation guarantee + empirical exactness。

两种结果都比现在更有理论价值。

# 八、1/6 UNCERTAIN 不建议粗暴增加所有 inner-MC

这里可以再升级一层统计协议。

既然只有 boundary case 不确定，可以采用 **anytime-valid sequential certification**。

例如为每个 boundary geometry 保持 confidence sequence：

[
[L_n,U_n]
]

持续增加 inner samples，直到：

[
U_n(P_{FA})<\alpha
]

且

[
U_n(P_{MD})<\beta
]

则 PASS；

或者：

[
L_n(P_{FA})>\alpha
]

或

[
L_n(P_{MD})>\beta
]

则 FAIL。

否则继续采样。

Confidence sequence 的好处正是：**允许根据中间结果决定什么时候停止，而仍然保持 time-uniform coverage**，这正适合你当前的 UNCERTAIN escalation。([IMStat](https://www.imstat.org/publications/aos/aos_49_2/aos_49_2.pdf?utm_source=chatgpt.com))

所以没有必要：

[
6\text{ cells}\times10\times MC
]

全部再跑一遍。

只升级那个 uncertainty boundary。

不过外层 geometry 泛化仍然是另一个问题。**inner-MC 能解决“这个 geometry 判断不准”，不能解决“3 个 geometry 能否代表总体”。**

因此最终论文至少应区分：

[
\text{conditional MC certificate}
]

和

[
\text{geometry-level generalization certificate}.
]

这个边界必须写清楚。
