基于最新这四份文档，我认为当前系统已经进入了一个很明确的阶段：

> **FRIDS-v2 核心算法暂时不要继续优化，接下来应该以“审计驱动优化”为主。**

原因是最新 G9A 已经证明：虽然局部价格 (D_y\approx0.23)、owner-vs-local deficit gap 约 2.11，而且局部动作相对理想动作约 67% 会发生变化，但把价格统一成 common-price oracle 后，worst-target delay 只改善约 **1.8%**，低于 2%。因此“局部 dual 不一致”不是当前性能瓶颈，文档已经明确给出 **freeze FRIDS-v2** 的结论。

所以当前正确的问题已经从：

[
\text{“FRIDS 公式还能怎么改？”}
]

变成：

[
\boxed{
\text{“系统还有哪些假设会导致论文结论失真？”}
}
]

我建议按 **5 个核心模块**做审计，而且有明确优先级。

------

# 一、最高优先级：系统级统计与泛化审计

这是现在**最应该先做**的，不是再写算法。

原因很简单：之前系统锐评已经发现，scenario variance 曾占总方差的 **69%–95%**，说明 MC seed 很多不等于场景泛化充分。虽然 FRIDS 后续已经扩展到多 scenario，但不同 gate 使用的场景数仍然不统一，例如 G9A 只有 3 个 scenario。

## 要审计什么

冻结：

- FRIDS-v2；
- token；
- owner；
- full mesh；
- calibration protocol；
- (K,Q)；
- 所有算法参数。

只变化：

[
\boxed{\text{scenario realization}}
]

建议正式跑：

[
(K,Q)\in
{(6,3),(8,4),(12,6),(16,8)}
]

每档至少：

[
10\sim20\text{ scenario seeds}.
]

每个 scenario 内用 paired MC。

不要只报告均值，要报告：

[
J_s=\max_qE_1[T_q],
]

以及跨场景：

[
\operatorname{median}(J_s),
\quad
P_{90}(J_s),
\quad
\max_sJ_s.
]

再给：

[
P_{\rm MD}^{max},
\quad
P_{\rm FA}^{max},
]

和 bootstrap CI。

### 这里真正需要回答的是

FRIDS-v2 的改进到底是：

[
\boxed{\text{平均有效}}
]

还是：

[
\boxed{\text{多数场景有效}}
]

还是只是：

[
\boxed{\text{少数场景特别有效}}.
]

------

# 二、第二优先级：感知证据链审计

我认为这是目前**最容易被通信/信号处理审稿人质疑的一层**。

当前 FRIDS 的核心价值是：

# [ g_{iq}

I_{iqa}^{+,post}s_{i,o_q}.
]

理论上已经很好，而且 final-observable KL 恒等式也闭合了。

但它的上游仍然是：

[
\text{OTFS/DD physics}
\rightarrow
(\mu_0,\mu_1,\Sigma_0,\Sigma_1)
\rightarrow
p_0,p_1
\rightarrow
I^+.
]

目前系统模型明确承认：

- OTFS 采用 moment-matched evidence；
- fixed waveform parameters；
- OTFS-grid 在固定总 time-bandwidth 下的 scaling 仍然是开放问题；
- RIS 还是 controlled path-loss 模型。

所以这里建议做：

[
\boxed{\text{Evidence-Chain Consistency Audit}}
]

而不是继续优化调度器。

------

## 2.1 重点审计四个量

对每个 UAV-target pair：

### A. 物理 SNR/SINR

[
\gamma_{iq}^{sense}
]

### B. DD-domain evidence separation

例如：

# [ \delta_{iq}

\mu_{1,iq}-\mu_{0,iq}.
]

### C. local information

[
I_{iq}^{+,sense}.
]

### D. final information

[
I_{iq}^{+,final}.
]

检查整个链条是否满足基本的数据处理关系：

[
I^{final}
\le
I^{post}
\le
I^{quant}
\le
I^{sense}.
]

之前检测信息理论已经证明这一方向，但现在要在**实际系统主线配置**上逐链重新审计。理论发展记录里已经把这一 data-processing chain 作为检测信息主线的一部分。

------

## 2.2 尤其需要审计 OTFS-grid 资源公平

现在有一个比较危险的问题：

如果改变：

[
N_d,\quad N_\tau
]

却没有固定：

[
B_{\rm waveform}T_{\rm frame},
]

那么 DD grid 更大可能只是偷偷增加 sensing resource。

所以必须做：

[
\boxed{
N_dN_\tau
\text{变化时保持总 sensing time-bandwidth 固定}
}
]

然后重新测：

[
I^+,\quad J,\quad P_{\rm MD}.
]

如果 OTFS 参数改变以后：

[
g_{iq}
]

基本不变，那论文里 OTFS 应该老老实实降级为：

> sensing evidence generation background。

如果明显改变 FRIDS 的服务价值排序，那 OTFS 才真正进入算法机制。

这个 audit 比重新加入 NOMP 有意义得多。

------

# 三、第三优先级：U2U 通信物理一致性审计

当前系统虽然已经有 airtime 层，但 G7 深审计实际上给出了一个很明确的负结果：

最初场景中的 30%–53% airtime reduction **不能跨场景稳定复现**，固定 (\lambda_{\rm base}) 在 critical regime 甚至产生约 14% 回退。

所以不要继续调：

[
\lambda_{\rm base}.
]

真正要审计的是：

> **当前通信模型本身是否合理。**

------

## 3.1 当前通信层有三个需要查的地方

### ① Shannon rate 只是 upper bound

目前：

# [ R_{ij}

W_c\log_2(1+\gamma_{ij})
]

被正确地标记为 capacity upper bound，而不是 throughput。

所以审计时至少比较：

[
R_{\rm Shannon}
]

与一个离散 MCS / efficiency factor：

# [ R_{ij}^{eff}

\eta_{\rm PHY}
W_c\log_2(1+\gamma_{ij}),
\qquad
0<\eta_{\rm PHY}<1.
]

这里先别优化 (\eta)。

只看系统性能对：

# [ \eta_{\rm PHY}

1,\ 0.7,\ 0.5,\ 0.3
]

有多敏感。

------

### ② full-mesh receive load

当前：

# [ B_i^{rx}

b_{\rm tok}(K-1)
]

是严格线性增长。

F0-G6 当前测试区内：

[
\rho_C=0.71<1,
]

所以目前还没绑定。

但这只是 (K=16)。

建议不改 topology，先扫：

[
K=16,24,32,48.
]

只问：

[
\boxed{
\text{什么时候 }\rho_C>1？
}
]

只有真的过 1，下一步才研究 sparse topology。

------

### ③ 通信崩溃的 graceful degradation

这是当前系统一个值得注意的模型缺口。

现有 zero-communication baseline 会：

[
P_{\rm MD}\rightarrow1.
]

也就是说当前系统是：

[
\text{有协同：很好}
]

和

[
\text{没协同：基本崩溃}.
]

文档把这一点明确列为 toy-grade 边界之一。

所以建议测试：

[
s_{ij}
\rightarrow
0
]

时，

[
P_{\rm MD}(s),\quad J(s)
]

到底是平滑退化还是相变式崩溃。

如果存在明显临界点：

[
s_c,
]

这甚至可以形成一个非常好的部署结论：

[
\boxed{
s>s_c
\Rightarrow
\text{cooperative mode},
}
]

[
s<s_c
\Rightarrow
\text{local fallback}.
}
]

这个比继续优化 airtime gate 更重要。

------

# 四、第四优先级：Owner 机制审计

这是我认为**下一轮最值得审计、但暂时不该直接改**的算法结构。

当前还是 fixed owner：

[
o_q.
]

系统文档自己明确承认 fixed owner 是当前 toy-grade assumption。

但是不能因此直接上：

> dynamic owner。

先做三个 oracle。

------

## 4.1 Fixed owner

当前：

[
o_q^{fixed}.
]

作为主线。

## 4.2 Best-static-owner oracle

对每个 scenario，在 episode 前离线选择：

# [ o_q^{static,*}

\arg\min_o
J_q(o).
]

episode 内不切换。

## 4.3 Dynamic-owner oracle

允许每周期理想选择：

[
o_q^*(t).
]

但只作为 offline upper bound。

------

然后定义：

# [ \Delta_{\rm static-owner}

## J_{\rm fixed}

J_{\rm best-static},
]

# [ \Delta_{\rm dynamic-owner}

## J_{\rm best-static}

J_{\rm dynamic}.
]

这样可以明确知道：

### Case A

[
\Delta_{\rm static-owner}<2%.
]

那么 fixed owner 根本不是问题。

**关闭 owner 方向。**

### Case B

[
\Delta_{\rm static-owner}>5%,
\quad
\Delta_{\rm dynamic-owner}\approx0.
]

说明只需要更合理的**离线 owner assignment**。

根本不需要动态 owner。

### Case C

[
\Delta_{\rm dynamic-owner}>5%.
]

才值得研究：

[
\boxed{\text{distributed dynamic responsibility transfer}}.
]

这会避免系统直接掉进一个新的复杂模块。

------

# 五、第五优先级：静态几何 / Mobility 审计

当前系统主线还是 static geometry。

但我建议**不要直接加 trajectory optimization**。

先做：

[
\boxed{\text{Frozen-Policy Mobility Sensitivity Audit}}
]

也就是：

> UAV 在动，但 FRIDS 算法不改。

设：

[
|p_i(t+1)-p_i(t)|
\le v_{\max}T_c.
]

已有 sensing mobility envelope 可以给出距离变化上界，Run Matrix 也已经有：

`run_sensing_mobility_envelope_gate.py`。

真正需要加的是：

每周期统计：

[
\frac{|g_{iq}(t+1)-g_{iq}(t)|}
{g_{iq}(t)}
]

以及 ranking change：

[
\Pr
\left[
\arg\max_qJ_{iq}(t+1)
\neq
\arg\max_qJ_{iq}(t)
\right].
]

再看：

## [ J_{\rm mobile}

J_{\rm static}.
]

如果：

[
<3%-5%,
]

说明 static-geometry abstraction 对当前时间尺度足够。

不需要 trajectory optimization。

如果：

[

> 5%-10%,
> ]

才引入：

[
g_{iq}(t+\tau)
]

的预测。

而不是直接 MAPPO 控轨迹。

# 六、还有一个必须单独做的“检测闭环审计”

这个我建议和前面五个模块并行，但它不是优化模块，而是 correctness audit。

当前 stopping 是 policy-matched numerical thresholds。

而 belief-state 层假设：

[
(p_0,p_1)
]

已知。

系统模型同时承认：

> residual monitor 能发现 erasure/success mismatch，但 flip-only mismatch 可能检测不到。

所以建议做：

[
\boxed{\text{Kernel-Mismatch Audit}}
]

只改变：

[
\epsilon_{\rm BSC}^{true}
\neq
\epsilon_{\rm assumed},
]

[
s^{true}
\neq
s^{assumed},
]

[
I^{true}
\neq
I^{assumed}.
]

检查：

[
P_{\rm FA},
\quad
P_{\rm MD},
\quad
E[T].
]

这里不是先做 robust algorithm。

首先要判断：

> 当前 calibration 到底对哪种 mismatch 敏感？

建议生死门：

如果在合理误差区间内：

[
P_{\rm MD}
\le
\beta+0.02,
]

且：

[
\Delta J<5%,
]

则关闭 robust detection layer。

只有明显越界再做鲁棒阈值。

# 九、优化逻辑以后必须改成“审计→分解→只修绑定项”

我建议后面所有工作严格采用：

[
\boxed{
\text{Audit}
\rightarrow
\text{Oracle gap}
\rightarrow
\text{Bottleneck classification}
\rightarrow
\text{One-variable repair}
\rightarrow
\text{Life-or-death gate}.
}
]

举例：

如果 owner audit 得到：

[
J_{\rm fixed}=3.60,
\quad
J_{\rm static-owner}=3.55,
\quad
J_{\rm dynamic}=3.52,
]

那就直接关闭。

不要因为“dynamic owner 听起来高级”继续做。

反过来，如果：

[
3.60\rightarrow3.20,
]

那才值得开新算法。

# 十、从当前状态看，我最推荐的下一次实验不是算法优化

而是一个**System Bottleneck Audit v2**。

只测试 4 个 oracle/gap：

[
\boxed{
\begin{aligned}
\Delta_{\rm sensing}
&=
J_{\rm current}-J_{\rm ideal\ evidence},\
\Delta_{\rm comm}
&=
J_{\rm current}-J_{\rm perfect\ U2U},\
\Delta_{\rm owner}
&=
J_{\rm current}-J_{\rm best\ static\ owner},\
\Delta_{\rm mobility}
&=
J_{\rm current\ policy@mobile}
-J_{\rm static}.
\end{aligned}
}
]

再配上已经完成的：

[
\Delta_{\rm dual}<2%.
]

那么你就能第一次得到一个非常清晰的：

[
\boxed{
\text{Current-system headroom decomposition}
}
]

例如最终可能变成：

[
\text{sensing 12%}

> 

\text{communication 8%}

> 

\text{owner 2%}

> 

\text{dual 1.8%}.
]

那下一步优化方向就完全不需要争论了。

------

## 最终判断

**当前算法本体 FRIDS-v2 不需要继续优化。**

现在最值得做的是把系统审计成三层：

[
\boxed{
\text{感知层}
\rightarrow
\text{通信层}
\rightarrow
\text{分布式任务层}
}
]

其中任务层基本已经过关；真正剩余的不确定性主要在：

[
\boxed{
\text{OTFS evidence真实性}
+
\text{U2U物理通信真实性}
+
\text{fixed owner}
+
\text{static geometry}
+
\text{场景泛化}.
}
]

我会把**下一步唯一主任务**定成：

[
\boxed{\textbf{System Bottleneck Audit v2}}
]

先不改任何算法，用 ideal-evidence、perfect-U2U、best-static-owner、mobile-stress 四个隔离 oracle 找出**第一大真实 headroom**。谁的 gap 超过 5%，下一轮只优化谁；其余全部冻结。这样比继续发明 FRIDS-v3 更符合当前系统已经达到的成熟程度。
