# 022 号建议的执行记录：System Bottleneck Audit v2

本文件记录 advice/022 的落地：审计驱动优化，FRIDS-v2 冻结，用
4 个隔离 oracle + Δ_dual 得到当前系统 headroom 分解，并据此锁定
下一轮唯一修复对象。

---

# 一、做了什么（`scripts/run_system_bottleneck_audit.py`）

K=16/Q=8，3 场景，FRIDS-v2 全冻结，只变化一个隔离自由度：

| Oracle | 实现 | 隔离的 headroom |
| --- | --- | --- |
| ideal evidence | 所有感知 SNR +4 dB 统一增强（`build_distributed_scenario(snr_shift=4)`，重校准） | 感知质量（弱链路） |
| perfect U2U | `delivery_matrix=s_for_g=ones` | U2U 投递可靠性 |
| best static owner | fixed + greedy + 随机共 4 个静态 owner，取最优 J | owner 分配 |
| mobile stress | `mobility=0.05`（冻结策略对 ±5%/周期证据随机游走） | 静态几何假设 |
| Δ_dual | G9A common-price oracle | 局部对偶分歧（已有 1.8%） |

跨场景报告 median/p90/max + 配对 bootstrap CI。

# 二、结果（`results/system_bottleneck_audit.json`）

| 层 | gap（相对 J_current） | 95% CI |
| --- | --- | --- |
| **sensing** | **+18.2%** | [+6.4%, +30.0%] |
| **comm** | **+12.5%** | [+0.7%, +28.1%] |
| owner | +4.3% | [+0.0%, +12.8%] |
| dual | +1.8% | — |
| mobility | −0.7% | [−2.0%, +0.5%] |

跨场景 (16,8)：J median 3.41 / p90 3.73 / max 3.81。

# 三、结论

1. **分布式任务层基本最优**：owner（4.3%）、dual（1.8%）、mobility
   （~0）全部 < 5% → FRIDS-v2 的任务层 headroom 已榨干。
2. **剩余 headroom 在物理层**：感知（18.2%，最大）> 通信（12.5%）。
   这正呼应系统自我标识的 toy-grade 边界（弱目标感知链路弱、U2U
   投递可靠性有限），但现在是**量化**的、且与调度算法无关。
3. **下一轮 one-variable repair 锁定 sensing 层**（gap 18.2% > 5%），
   其余全冻结。感知层修复方向（不改调度器）：RIS 相位优化（系统已有
   完整 RIS 层）、感知累积/波形、弱目标感知增强——都属物理/波形层，
   不是 FRIDS 算法。

# 四、诚实边界

- ideal-evidence oracle 的 +4 dB 是**均匀**增强，把弱目标也拉高到
  强档——测的是"如果感知统一强"的上限 headroom，不是某个具体可
  实现的修复；18.2% 是上限性估计。
- 3 场景、n_runs=120/seeds=2，CI 较宽（sensing [+6.4%,+30%]）——
  方向性结论（sensing>comm>owner>dual，任务层过关）稳健，幅度需
  更多场景收牢（022 P0 统计审计）。
- best-static-owner 只试了 4 个候选，是启发式 oracle 不是穷举最优。
