# 013 号建议的执行记录：F0-G7 Physical-Airtime Reporting Gate

本文件记录 advice/013 的落地：把 U2U 从 bit 账本升级为波形导出的
airtime 约束，并增加 report/no-report 唯一自由度。结果与 013 的预期
部分一致、部分相悖，这里如实记录，供下一轮（G8）与论文使用。

---

# 一、执行了什么

## 1.1 物理 airtime 模型（`uav_otfs_isac/airtime.py`）

- 链路速率取**容量上界**（不声称吞吐率）：

  `R_ij = W_c * log2(1 + gamma_ij)`，

  `gamma_ij` 由交付成功反解对数正态 outage 律得到
  （`SNR = threshold + sigma * Phi^-1(s_ij)`），因此容量速率与
  outage 成功率来自**同一条 U2U 链路的统计**，而感知信道保持独立
  （满足 SYSTEM_MODEL §5 的通信/感知解耦原则）。

- token airtime：`tau_ij = b_tok(Q) / R_ij`（秒/周期，终于有物理单位）。
- 全网格接收负载：`L_i = sum_{j != i} z_j * tau_ji`；
  超载时按 `min(1, T_air / L_i)` 做队溢出丢弃（Theorem 4.102）。

## 1.2 report/no-report 门（Lemma 4.99/4.100/4.101/4.103）

- 价格 `lambda_i = lambda_base + lambda_dual_i`：
  - `lambda_base`：任务机会成本基线（感知/频谱机会成本，呼应
    F0-A 的 n^-2 律），由 Gate 在**小网格**上诚实扫描；
  - `lambda_dual`：对本地观测接收负载比做对偶上升，冷启动用
    本地稀缺度预测 `rho_est_i = sum_j tau_ij / T_air`（对称全网格下
    严格局部可算），使价格在拥塞区**立即生效**而非在短检测视界内
    慢慢爬升。
- 两种取值定义都被测量（Lemma 4.101）：
  - `deficit`：严格联合-LP 对偶 `y*g/(D+eps) - lambda*c_air`
    （013 §2 原式）；
  - `info`：把价格也按 deficit 归一化，`D` 抵消，退化为比较
    min-max 加权信息 `y*g` 与 airtime 价格。

- 传感/任务完全冻结：目标选择在所有模式下都是冻结的 FRIDS-v2
  `argmax y*g/(D+eps)`，价格只改 `z_i`——因此 always-report 基线
  与价格参数无关（这是本轮修掉的一个真实 bug：上一版价格泄漏进
  了目标选择，导致基线随 `mu_c` 漂移）。

## 1.3 Gate（`scripts/run_airtime_reporting_gate.py`）

K=16, Q=8, scenario seed 0；三个通信状态
`rho_full ~ {0.5, 1.0, 1.5}`（非拥塞/临界/拥塞）× 五个方法
（always / random-drop / periodic / value-triggered / oracle）× 两个
value mode × 6 个 lambda_base。主指标 `J = max_q E1[T_q]`，同时报告
`P_MD^max`、U2U airtime、tx reports/UAV、rx load/UAV。

# 二、结果（`results/airtime_reporting_gate.json`）

| regime | 方法 | J | P_MD^max | tx/UAV | airtime 削减 | budget-feasible |
| --- | --- | --- | --- | --- | --- | --- |
| 0.5 | always | 2.86 | 0.028 | 1.00 | - | 1.00 |
| 0.5 | value (deficit, lb=0.4) | **2.85** | 0.028 | 0.47 | **52.8%** | 1.00 |
| 1.0 | always | 2.86 | 0.028 | 1.00 | - | 1.00 |
| 1.0 | value (deficit) | **2.85** | 0.028 | 0.47 | **52.8%** | 1.00 |
| 1.5 | always | 3.31 | 0.027 | 1.00 | - | 0.00 |
| 1.5 | value (info, lb=0.1) | **3.23** | 0.028 | 0.89 | 11% | 0.11 |
| 1.5 | random (等量) | 3.34 | 0.027 | 0.89 | - | 0.11 |
| 1.5 | oracle | 3.43 | 0.027 | 0.62 | - | 1.00 |

Gate 裁决：**adopted with caution（单门通过）**。

- **非拥塞/临界区：deficit mode 通过生命门**——airtime 削减 52.8%，
  `Delta J = -0.4%`（检测延迟不降反升 0.4 个噪声级以内）。这是
  **明确的通信效率收益**：一半的 U2U 开销是低价值的。
- **拥塞区：未过 5% 延迟改善门**。info mode 相对 always +2.5%、
  相对等量 random +3.3%（选择价值存在），但最坏目标延迟是
  **总量信息驱动**的，报告级选择对 `max_q E[T_q]` 的杠杆有限；
  且归一化价值选择（`y*g/D`）把 airtime 损失集中在高 deficit 目标上
  （其报告归一化价值天然小），所以连中心 oracle（贪婪密度准入）
  都比不过均匀随机丢弃。

# 三、这个结果说明了什么（理论含义）

1. **013 §2 的 Lemma 成立并被数值验证**：没有 no-report 动作时，
   公共加法通信价格是 NO-OP；配 no-report 动作后价格才真正改变
   决策。G7 的实现严格满足这一点（测试 `test_common_price_without_
   idle_is_noop`）。

2. **013 的“第一版”`y*g/(D+eps) - lambda*tau` 是严格联合-LP 对偶**
   （我补了推导：对 airtime 约束加 Lagrangian，x 驻值给出
   `y*g/D - sum_j lambda_j*tau_ij`），但它对**延迟目标**是
   反最坏目标的。这是本轮最重要的负面结论：LP 目标（归一化进度 z）
   与延迟目标（max E[T]）不一致（呼应 F0-D 的分解），airtime 准入
   继承了这一偏差。

3. **airtime 的真实价值在“可行性”层面而非“延迟”层面**：它把
   不可行的拥塞帧变成可优雅降级（budget-feasible 分数从 0 提升），
   并给出 ~50% 的通信削减而几乎不损检测。这对 ISAC 的“通信-感知
   兼顾”叙事是实打实的贡献——不是“更快”，而是“同样好但通信省一半”。

# 四、下一步建议（按 013 的优先级）

013 说：G7 过不了就关闭 admission 方向。本 Gate **单门通过、且拥塞门
未过**，因此**不继续调 threshold**（避免过拟合），也不把
value-triggered 当作延迟改善器。正确做法：

1. **把 G7 定位为通信效率层**（论文里写成“airtime-feasible FRIDS
   reporting”，贡献是可行性/效率而非延迟），保留已通过的
   非拥塞/临界结果。
2. **按 013 推进 G8（证据相关性审计）**：先做 F0-G8A 不动 FRIDS，
   测 `sum_i g_iq` 相对联合 `G_q(S)` 是否高估（受控 `rho_s`），
   冗余比 `R_q = 1 - G_q(S)/sum g_iq` 显著再考虑 conditional-KL
   调度。G8 的理论价值 013 认为可能高于 G7，且与本次“报告级选择
   杠杆有限”的结论互补——因为相关性正是报告级去冗余的**信息论**依据。
3. 论文不要写“事件触发通信”或“首次 airtime-aware 调度”；新意落在
   **detection-deficit × final-observable reliable information ×
   physical airtime price** 的耦合，以及“airtime 价值在可行性层”
   这个诚实定位。
