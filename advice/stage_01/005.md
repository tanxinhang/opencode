现在可以比较明确地做一次“系统级纠偏”了。结合你上传的 `005.md`，我认为前面几轮讨论最终应该收敛成三个不可动摇的原则：

[
\boxed{
\textbf{Distributed-first}
+
\textbf{Deployable-first}
+
\textbf{Problem-first}
}
]

也就是说：

- **分布式执行是硬约束**，不是未来扩展；
- **可部署是算法选择标准**，Exact 只做审计；
- **NOMP、MAPPO、Bellman、dual、rollout 都不是研究身份**，谁适合解决问题谁留下。

`005.md` 已经把“Exact-first → Deployable-first”的纠偏讲清楚了：不再追求更复杂的 Pareto Bellman / joint exact DP，而将 Exact 降为小规模 benchmark、结构验证和少量 teacher 数据。
现在需要进一步把**分布式信息结构**补进这套逻辑。

------

# 一、重新锁定项目定位

当前项目建议正式定义成：

[
\boxed{
\textbf{Communication-Constrained Distributed Multi-UAV}
}
]

[
\boxed{
\textbf{Task-Oriented Cooperative Detection}
}
]

中文就是：

> **通信受限条件下的分布式多 UAV 任务驱动协同检测。**

核心问题不是“求一个资源分配最优解”，而是：

> 在没有中心协调器、每架 UAV 只能使用本地观测以及实际收到的 U2U 信息时，如何以有限的通信、感知、能量和计算资源，实现稳定、低开销、面向弱目标的协同检测？

这里有四个永久锚点：

[
\boxed{
\text{Distributed execution}
}
]

[
\boxed{
\text{Limited U2U communication}
}
]

[
\boxed{
\text{Multi-target cooperative detection}
}
]

[
\boxed{
\text{Deployable online decision}
}
]

以后 RIS、MAPPO、NOMP、Bellman、OTFS probing、movement 都必须围绕这四件事服务。

------

# 二、当前 `SYSTEM_MODEL` 最大的第一处偏差：`one fusion center`

最新系统模型开头仍然明确假设：

> one fusion center。

这和现在重新确认的研究定位直接冲突。

因此这是 **P0 级修改**。

主系统不能再写：

[
\text{UAV reports}
\rightarrow
\text{fusion center}
\rightarrow
\text{global decision}.
]

而应改成：

# [ \boxed{ a_{i,t}

\pi_i(\mathcal I_{i,t})
}
]

其中 UAV (i) 的信息集：

# [ \boxed{ \mathcal I_{i,t}

\left{
o_{i,0:t},
m_{j\rightarrow i,0:t},
j\in\mathcal N_i(t)
\right}.
}
]

即：

- 自己的局部 sensing evidence；
- 自己能测的 U2U link state；
- 邻居**真正成功送达**的 Token；
- 自己过去的动作与本地内部状态。

禁止直接访问：

[
\boxed{
\text{global positions}
,\quad
\text{global channel matrix}
,\quad
\text{global beliefs}
,\quad
\text{global target state}
}
]

来产生部署动作。

这一个定义必须写进系统模型。

它比以后用不用 MAPPO 更重要。

------

# 三、分布式不等于“所有 UAV 必须完全一致”

这一点也要避免重新跑偏。

没有必要把系统变成：

# [ L_{1,q,t}

# L_{2,q,t}

# \cdots

L_{K,q,t}.
]

真正部署时，UAV 本来就可能因为：

- packet loss；
- delay；
- topology；
- heterogeneous sensing；
- quantization；

得到不同 belief。

所以定义：

# [ \boxed{ L_{i,q,t}

\log
\frac{
P_i(H_q=1|\mathcal I_{i,t})
}{
P_i(H_q=0|\mathcal I_{i,t})
}.
}
]

每架 UAV 维护自己的：

# [ \mathbf L_{i,t}

[L_{i,1,t},\ldots,L_{i,Q,t}].
]

局部观测后：

# [ L_{i,q,t}^{+}

L_{i,q,t}
+
\ell_{i,q,t}.
]

收到邻居消息：

[
m_{j\rightarrow i,q,t}
]

以后进行：

# [ L_{i,q,t+1}

\mathcal F_i
\left(
L_{i,q,t}^{+},
m_{j\rightarrow i,q,t}
\right).
]

于是新的理论问题不是追求完全共识，而是：

[
\boxed{
\textbf{belief 不一致情况下，分布式决策是否仍然稳定和有效？}
}
]

这比单纯 consensus 更贴合部署。

------

# 四、建议保留“Target Owner”，但必须是分布式角色

你之前系统里一直有 ownership / role / pairing 的思想，这一点反而非常适合重新利用。

对每个目标 (q)，指定：

[
o_q(t)\in{1,\ldots,K}.
]

但 owner 不是 fusion center。

它只是该目标当前的**局部责任节点**。

例如负责：

- 保存该目标较完整的 local belief；
- 接收附近 UAV 的 evidence token；
- 维护 stopping status；
- 广播很小的 urgency / request token。

不同目标：

[
o_1(t),o_2(t),\ldots,o_Q(t)
]

可以由不同 UAV 承担。

因此系统实际上是：

[
\boxed{
\text{distributed sensing}
+
\text{distributed fusion responsibility}
+
\text{distributed resource coordination}.
}
]

而不是一个 FC。

------

# 五、这样“通信”终于重新成为核心研究变量

过去很多版本的问题是：

> 已经决定要协同，然后尽量把报告传好。

新的系统应该问：

[
\boxed{
\textbf{有限的 U2U bit 到底应该用来传什么？}
}
]

建议把总通信预算拆成：

# [ \boxed{ B_{\mathrm{U2U}}

B_{\mathrm{evidence}}
+
B_{\mathrm{coord}}.
}
]

### Evidence information

例如：

[
\hat L_{i,q},
\quad
\text{soft evidence},
\quad
\text{confidence}.
]

用于提升检测本身。

### Coordination information

例如：

[
\text{urgency},
\quad
\text{owner},
\quad
\text{bid},
\quad
\text{resource price},
\quad
\text{intent}.
]

用于避免：

- 重复感知；
- 多 UAV 抢同一目标；
- 弱目标长期饿死；
- 持续切换。

于是一个非常有研究价值的问题自然出现：

[
\boxed{
\text{Evidence communication}
\quad\text{vs}\quad
\text{Coordination communication}.
}
]

这比单纯“减少 packet bits”更有深度。

------

# 六、Token 应该重新成为分布式系统的接口

不建议各 UAV 互相传完整 belief vector、完整 channel matrix。

应该建立小型任务 Token，例如：

# [ \boxed{ m_{i\rightarrow j,t}

{
q,
\hat L_{i,q},
u_{i,q},
r_{i,q},
\chi_{ij},
a_i^{\mathrm{intent}},
t_{\mathrm{stamp}}
}.
}
]

不意味着最终全部字段都要发送。

而是从这里通过消融找到最小充分信息。

其中可能：

- (\hat L_{i,q})：量化 evidence；
- (u_{i,q})：不确定性；
- (r_{i,q})：urgency；
- (\chi_{ij})：报告可靠性；
- intent：下一周期准备感知谁；
- timestamp：AoI。

最终目标是找到：

[
\boxed{
\text{minimum task-sufficient token}.
}
]

这和最初“减少通信交换，同时维持检测性能”的研究动机重新对齐了。

------

# 七、真正部署的算法架构也要改

`005.md` 里面原来的 deployable 流程是：

[
\text{local score}
\rightarrow
\text{small bid}
\rightarrow
\text{lightweight scheduler}.
]



这里仍然隐含一个 scheduler。

纠偏以后变成：

[
\boxed{
\begin{array}{c}
\text{Local evidence update}\
\downarrow\
\text{Local belief}\
\downarrow\
\text{Local action-value / urgency computation}\
\downarrow\
\text{U2U compact token exchange}\
\downarrow\
\text{Distributed conflict resolution}\
\downarrow\
\text{Local action execution}
\end{array}
}
]

没有中心调度器。

------

# 八、一个合适的分布式动作价值形式

可以保留前面比较好的任务价值思想，但变成本地量：

# [ \Delta_{i,q,a}

## \widehat T_{i,q}(t)

\mathbb E[
\widehat T_{i,q}(t+1)|a
].
]

然后 UAV (i) 计算：

# [ \boxed{ J_{i,q,a}

## \nu_{i,q} \Delta_{i,q,a}

## \lambda_{i,B}B(a)

## \lambda_{i,E}E(a)

## \lambda_{i,T}T(a)

\psi_{i,q,a}.
}
]

这里新增：

[
\psi_{i,q,a}
]

作为邻居冲突/拥塞价格。

它可以来源于邻居广播的 intent 或 bid。

因此每架 UAV 最终：

# [ a_{i,t}

\arg\max_{a}
J_{i,q,a}.
]

但如果邻居都选择同一个目标，则进行一次非常轻量的：

[
\boxed{
\text{auction / priority resolution / bounded negotiation}.
}
]

这才是真正的 deployable distributed scheduler。

------

# 九、不要让“分布式”重新变成无限 consensus

另一个潜在跑偏点是：

> 既然分布式，就做越来越复杂的 consensus。

不建议。

通信受限本身就是问题，因此必须限制协调轮次，例如：

[
\boxed{
R_{\mathrm{coord}}\le1\text{ 或 }2
}
]

每周期只允许：

1. broadcast local token；
2. optional conflict reply。

到此停止。

不要求 consensus convergence。

论文研究的应该是：

[
\boxed{
\text{bounded-message distributed coordination}.
}
]

而不是：

[
\text{asymptotic consensus}.
]

这更符合无人机在线部署。

------

# 十、NOMP、MAPPO、dual、rollout 都重新放回候选箱

现在任何算法都不能提前绑定。

### NOMP

如果证明 1 次 local swap：

[
\Delta T_{\rm worst}
]

明显下降且：

[
T_{\rm compute}
]

很低，就作为：

[
\text{bounded local repair}.
]

否则删掉。

------

### MAPPO

只允许：

# [ a_{i,t}

\pi_\theta(\mathcal I_{i,t}).
]

CTDE 可以用于训练 critic。

但 deployment actor 绝不能看到 global state。

如果它不能明显优于：

[
\text{distributed greedy / price / auction},
]

也删掉。

------

### Bellman / rollout

只用于 local action evaluation：

[
\Delta_{i,q,a}
]

或者短视 rollout。

不能重新长成 global joint Bellman。

------

### Exact

彻底放到：

[
\boxed{\text{offline audit}}
]

位置。

这点和 `005.md` 完全一致。

------

# 十一、还要纠正现在的资源模型

当前研究报告仍然存在类似：

[
\sum(p_{qr}+b_{qr})\le B
]

的统一“预算”。

如果现在明确走部署型分布式系统，这一表述应该正式淘汰。

每架 UAV (i) 单独有：

[
\boxed{
B_{i,t}^{\mathrm{U2U}}
}
]

通信预算，

[
\boxed{
E_{i,t}^{\mathrm{sense}}
}
]

能量预算，

以及：

[
\boxed{
T_{i,t}^{\mathrm{compute}}
}
]

计算/决策时限。

动作成本：

[
\boxed{
c_i(a)=
[
b_i(a),
e_i(a),
t_i^{\mathrm{air}}(a),
t_i^{\mathrm{comp}}(a)
].
}
]

这也是分布式的重要区别：

不是只有一个：

[
B_{\mathrm{global}}.
]

而是每个节点都有本地约束。

------

# 十二、真正的优化问题也应该改成“分布式可行策略”

整个问题可以正式写成：

[
\boxed{
\begin{aligned}
\min_{{\pi_i}*{i=1}^K}\quad&
\max_q E[T_q]
\
\text{s.t.}\quad&
P*{FA,q}\le\alpha_q,
\
&
P_{MD,q}\le\beta_q,
\
&
a_{i,t}=\pi_i(\mathcal I_{i,t}),
\
&
b_{i,t}\le B_{i,t},
\
&
e_{i,t}\le E_{i,t},
\
&
t_{i,t}^{\mathrm{comp}}\le T_{\rm cycle},
\
&
R_{\mathrm{coord}}\le R_{\max}.
\end{aligned}
}
\tag{P-DIST}
]

最关键的约束其实是：

[
\boxed{
a_{i,t}=\pi_i(\mathcal I_{i,t}).
}
]

它把 centralized oracle 和真实部署策略彻底分开。

# 十三、Exact oracle 应该用于“分解损失”，而不是当目标

以后 exact 最大的价值是得到一个 reference：

[
J_{\rm global}^{\star}.
]

然后我们真正关注：

[
J_{\rm local}
]

[
J_{\rm dist-full}
]

[
J_{\rm dist-token}
]

[
J_{\rm deploy}.
]

建议做这样的 gap decomposition：

# [ \boxed{ \Delta_{\rm decentral}

## J_{\rm dist-full}

J_{\rm global}^{\star}
}
]

表示没有中心信息的损失。

再定义：

# [ \boxed{ \Delta_{\rm comm}

## J_{\rm dist-token}

J_{\rm dist-full}
}
]

表示有限 U2U 的损失。

以及：

# [ \boxed{ \Delta_{\rm alg}

## J_{\rm deploy}

J_{\rm dist-token}^{best}.
}
]

这样：

# [ \boxed{ \Delta_{\rm total}

\Delta_{\rm decentral}
+
\Delta_{\rm comm}
+
\Delta_{\rm alg}.
}
]

这比“我的算法距离 Exact 3.9%”有解释力得多。

------

# 十四、下一阶段不要先优化算法，先做一个真正的纠偏 Gate

我建议现在直接停止 D3-A 那种 centralized deployment profile。

改为：

[
\boxed{
\textbf{Gate F0 — Distributed Information Audit}
}
]

固定一个中等规模：

[
K=6\sim8,
\qquad
Q=3\sim4.
]

四个系统：

### A. Centralized Oracle

仅 benchmark。

允许 global information。

------

### B. Distributed Full-Message

严格：

[
a_i=\pi_i(\mathcal I_i),
]

但邻居之间允许发送完整任务状态。

测去中心化本身代价。

------

### C. Distributed Compact-Token

只交换真正准备部署的有限 Token。

测压缩/通信限制代价。

------

### D. Local-Only

完全不协作。

作为：

[
\text{zero-communication baseline}.
]

# 十六、紧接着做 F1：Token value decomposition

如果 F0 证明协同有价值，下一步不要直接 MAPPO 或 NOMP。

先研究：

[
\boxed{

\boxed{

\quad \text{vs}\quad

\boxed{

这实际上又和你最早研究的 soft information selection 主线重新接上。

# 十八、分布式系统还有一个必须成为正式指标的东西：稳定性

不能只看：

[
P_D,\quad T.
]

还需要：

[
\boxed{
\text{decision conflict rate}
}
]

[
\boxed{
\text{role switch rate}
}
]

[
\boxed{
\text{duplicate sensing rate}
}
]

[
\boxed{
\text{belief disagreement}
}
]

例如：

# [ D_L(t)

\frac1{|\mathcal E_t|}
\sum_{(i,j)\in\mathcal E_t}
|L_{i,q,t}-L_{j,q,t}|.
]

但是注意：

[
D_L(t)\to0
]

不应该成为必须条件。

真正要求的是：

[
\boxed{
\text{belief 可以不同，actions 不能长期振荡和冲突。}
}
]

这是很值得研究的分布式特点。

## 当前最重要的纠偏结论

从今天这个版本开始，我建议明确停止三条惯性：

[
\boxed{\text{停止 Exact-first}}
]

[
\boxed{\text{停止 Fusion-center-first}}
]

[
\boxed{\text{停止 Algorithm-first}}
]

替换成：

[
\boxed{
\textbf{Distributed + Deployable + Task-Oriented}
}
]

当前已有的 Exact、Bellman、NOMP、MAPPO、RIS、共识结果都不需要删除，但必须重新分类为 **oracle、baseline、sandbox 或可选模块**。现有理论文档已经积累了大量 Exact、NOMP、MAPPO、共识等结果；真正需要做的是重新建立“谁是主线、谁是工具”的层级，而不是继续增加第 25 个理论阶段。

**接下来最应该执行的不是继续调 dual/rollout，也不是继续做 Exact，而是先修改 `SYSTEM_MODEL` 的系统边界：删除 one-fusion-center 部署假设，加入 (\mathcal I_{i,t})、局部 belief、U2U Token、分布式动作约束和节点级资源预算；然后立即做 F0 Distributed Information Audit。**

只要 F0 做完，我们就能第一次非常清楚地知道：当前项目真正应该往**信息压缩、分布式协调、稳定性，还是学习方法**中的哪一个方向继续深入，而不是靠算法名称决定研究方向。
