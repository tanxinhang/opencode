# 二、还有 5 个正式门级别的问题需要一起修

## P0-2：当前不存在真正的 paired-CRN

runner 里写了 `paired_bootstrap_ci()`，注释也说两个 scheduler 使用相同外生 realization。

但实际随机数路径不是这样。

FRIDS-v2 是：

```python
rng = np.random.default_rng(seed)

for r in range(n_runs):
    H = rng.random(q) < 0.5
    ...
```

一个连续 RNG 流。

CA-FRIDS 则是：

```python
for r in range(n_runs):
    rng_r = np.random.default_rng([seed, r])
    H = rng_r.random(q) < 0.5
```

每 run 重新建立独立流。

因此即使两个算法都传 `seed=7+mc`：

[
H^{\rm v2}*{r,q}\neq H^{\rm CA}*{r,q}
]

一般都不相同，更不用说 observation、link outage 和 admission 随机量。

而且两个策略动作不同后，顺序调用 `rng.random()` 的次数也不同，所以即使简单统一成同一个 `rng_r`，后续随机数仍然会错位。

### 正确修法

不要再依赖“同 seed = CRN”。

建立**外生随机 tape**：

[
\mathcal U=
{
U^H_{r,q},
U^{obs}*{r,t,i,q,a},
U^{link}*{r,t,i,j},
U^{adm}_{r,t,j,i}
}.
]

所有算法访问同一份 tape：

- `H[r,q]` 完全一致；
- 某 UAV 选择不同 action 时，用相同基础 uniform 经对应 CDF 映射；
- link survival 使用固定 `U_link[r,t,i,j]`；
- admission tie-break 使用固定随机 tape。

这样才能真正说：

# [ \Delta_r

J_r^{CA}-J_r^{v2}
]

是 paired sample。

即：

1. 每 300-run MC block 先求一次 worst target；
2. 得到 100 个 worst-target estimates；

它不是：

# [ \boxed{ J_g

\max_q
\frac{
\sum_{\text{30k trials},,H_q=1}T_q

}

sum_delay2_H1[q]

\frac{\sum T_q}{N_{H_1,q}},

100 个 MC block 只用于方差估计，不应该改变 objective 定义。

# 五、congested comparison 还有一个更重要的公平性问题

你当前说：

> v2 和 CA 已经共享 hard-admission capacity model。

严格看代码，并没有。

### CA

CA 的逻辑是：

[
\text{candidate}
\rightarrow
\text{receiver admission}
\rightarrow
\text{airtime consumed}
\rightarrow
\text{link Bernoulli}.
]

所以即使链路 outage，airtime 也已经消耗。

这个通信逻辑是合理的。

### FRIDS-v2

v2 当前是先：

```python
if rng.random() > delivery[uav, neighbor]:
    continue
offer[neighbor].append(uav)
```

也就是说：

[
\text{link Bernoulli}
\rightarrow
\text{successful packet}
\rightarrow
\text{capacity admission}.
]

所以 link outage 的 transmission **完全不占 receive capacity**。

这和 CA 的物理口径不一样。

而且 v2 的容量是：

```python
cap_tokens = (K-1)/rho_full
```

一个统一 token-count cap；

CA 是真实异质：

[
c_{ij}=\tau_{ij}/T_{\rm air},
]

其中 (\tau_{ij}) 取决于链路速率。

因此当前：

[
3.83%
]

不能解释成“在完全相同物理容量下 CA 对 v2 的收益”。

### 正确修复

抽一个共同函数：

[
\boxed{\texttt{receiver_hard_admission()}}
]

两个 scheduler 都使用：

1. 所有 candidate 先形成；
2. 根据相同 (\tau_{ij})；
3. 满足

[
\sum_{i\in A_j}\tau_{ij}\le T_{\rm air};
]

1. 再对 admitted packet 采样 link success；
2. admitted 但 outage 的 airtime 仍记账。

这样 congested gate 才真正公平。

# 八、如果最后真的需要“备份”，不要恢复 full mesh raw evidence

我不建议回到：

[
O(K^2)
]

的 token replication。

更合适的是 owner 广播一个**任务充分状态**，例如：

[
\boxed{
(D_q,\ r_q,\ \text{ACK/state version})
}
]

甚至只广播 quantized owner state change。

本质上是：

[
\text{raw evidence replication}
\rightarrow
\text{sufficient-state synchronization}.
]

这和最近 IEEE Transactions on Networking 的 goal-oriented distributed belief processing 思路也更一致：它同样利用公开 ACK/公共信息让节点推断其他节点的信息状态，而不是复制全部原始观测。([帕多瓦大学研究](https://www.research.unipd.it/retrieve/bd3d2509-7171-4b37-82db-5fc8c770de9f/Goal-Oriented_Medium_Access_With_Distributed_Belief_Processing.pdf?utm_source=chatgpt.com))

所以以后如果做这个方向，创新点不能写：

> “distributed belief sharing”。

而应该写成：

> **sequential-detection sufficient-state bus with certified decision preservation**。

# 九、如果 global-simplex 真跑以后仍有 5–10% regression，我更推荐的算法升级不是 evidence backup

那时我优先考虑一个更干净的：

[
\boxed{\text{Entropy-Regularized CA-FRIDS}}
]

因为 global price 很容易造成多个 UAV 同周期同步追同一个 target，即 common-price herding。

把当前硬 argmax：

# [ q_i^*

## \arg\max_q \left[ \pi_q g_{iq}

\lambda_{o(q)}c_{iq}
\right]
]

改成熵正则化 primal response：

# [ x_i^*

\arg\max_{x_i\in\Delta_{Q+1}}
\sum_qx_{iq}J_{iq}^{CA}
+
\tau H(x_i),
]

其中 idle 也是一个 action。

闭式：

# [ x_{iq}

\frac{
e^{J_{iq}^{CA}/\tau}
}{
1+\sum_p e^{J_{ip}^{CA}/\tau}
}.
]

然后每 UAV 本地 Gumbel-max/sample 一次。

它有几个优点：

- 不增加新通信；
- 不需要 MARL；
- 保持原始-对偶来源；
- 减少同步 herd；
- (\tau\to0) 自动恢复现有 CA；
- 正则化 gap 有标准

[
O(\tau\log(Q+1))
]

上界。

但这一项应该放在 **P3.6-D 证明 herding 确实存在之后**，而不是现在直接加。
