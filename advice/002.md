# 一、真正的问题不在“下一个优化什么”，而在研究方法错了

目前采用的是：

[
\text{找最大 oracle gap}
\rightarrow
\text{优化对应模块}
\rightarrow
\text{再找最大 oracle gap}
\rightarrow\cdots
]

这套方法适合**工程系统调优**，但不适合作为论文研究主线。

因为一个系统永远都有 residual gap。

例如：

[
\Delta_{\rm sensing}=18.2%,
\quad
\Delta_{\rm comm}=12.5%,
\quad
\Delta_{\rm owner}=4.3%.
]



这里最大的概念误区是：

> **oracle headroom ≠ 可优化的算法 headroom。**

例如 sensing 的 +18% 来自“理想 +4 dB evidence”。

但 G10-B 马上证明：

[
\text{同能量重新分配}\not\Rightarrow \text{性能提升},
]

所以这 18% 很大一部分其实是**硬件能力差距**，不是算法空间。

同样：

[
\Delta_{\rm comm}=12.5%
]

来自 **perfect U2U**。

这并不意味着存在一个通信调度算法可以拿回来 12.5%。

前面其实已经试过：

- token fidelity：基本没用；
- fresh intent：反而退化；
- airtime report gate：跨场景不稳定；
- reliability robust layer：基本 no-op。

因此现在直接转向“通信 12.5%”的话，**极有可能再次重演 G10→G11**。

------

# 二、所以现在应该做一个根本性的“停止规则”

我建议从现在开始：

> **不再根据 residual headroom 自动产生新的研究点。**

研究点正式冻结。

我认为真正已经被实验和理论筛选出来的核心研究问题，不应该再叫：

> Reliable Information Shaping

因为这个名字仍然诱导我们继续寻找 waveform/power/communication shaping 变量。

更应该收敛成：

# **通信受限分布式多 UAV 序贯协同检测**

核心问题：

[
\boxed{
\text{在局部信息、有限 U2U 和检测可靠性约束下，
如何进行可扩展的分布式任务决策，
并刻画其可行性与性能边界？}
}
]

英文可以定位成：

> **Distributed Task-Oriented Sequential Detection under Communication Constraints**

OTFS-ISAC 是**物理应用场景**，不是不停被优化的研究对象。

------

# 三、这样回头看，真正成功的主线其实已经出现了

不是 G10，也不是 G11。

而是从 F0 到 FRIDS-v2/G6 这一段。

## 1. 问题

部署系统严格满足

# [ a_{i,t}

\pi_i(\mathcal I_{i,t}),
]

也就是说每架 UAV 只能使用：

- 本地观测；
- 实际收到的 U2U 消息；
- 自己的历史。

优化

[
\boxed{
\min_{\pi_1,\ldots,\pi_K}
\max_q E_1[T_q]
}
]

subject to

[
P_{{FA},q}\le\alpha_q,
\qquad
P_{{MD},q}\le\beta_q,
]

以及节点级通信、感知、计算约束。

这本身就是一个稳定的研究问题。

------

## 2. 中间物理接口

定义可靠检测信息：

# [ g_{iq}

s_{i,o_q}
I_{iq}^{+,\mathrm{post}}.
]

这不是新的研究点，而是：

> **通信层和感知层向任务层提供的接口量。**

OTFS、BSC、擦除、SNR、量化都只负责决定 (g_{iq})。

以后不再为了优化 (g) 而不断增加算法。

------

## 3. 核心算法

FRIDS-v2：

# [ \boxed{ J_{iq}

y_q^{(i)}
\frac{g_{iq}}
{D_q^{(i)}+\epsilon}
}
]

本质是：

[
\text{任务紧迫度}
\times
\text{可靠信息供给}.
]

它不是 Top-K，也不是 marginal gain 的简单改名，而是由 demand-normalized min-max relaxation 推出来的局部 primal-dual 规则。

而且这一部分有真正的正结果：

[
(6,3): -7.6%,
]

[
(8,4): -12.7%,
]

[
(12,6): -7.6%,
]

[
(16,8): -15.1%,
]

并保持严格局部执行和误差约束。

这才是一个应该继续守住的核心。

# 四、理论核心也已经有了，不需要再“创造一个新理论方向”

以及

\max_{S\subseteq\mathcal Q}

{H F(S)}

# 五、现在最应该做的“升华”，其实是从算法论文变成“边界 + 算法”论文

论文问题可以进一步压缩成两个科学问题。

### Q1：什么时候能完成？

给定：

[
K,Q,{g_{iq}},B_{\rm U2U},H,
]

是否存在分布式策略满足

[
P_{FA}\le\alpha,\qquad
P_{MD}\le\beta ?
]

这对应 **feasibility law**。

------

### Q2：如果可完成，怎么接近边界？

在严格局部信息约束下：

[
a_{i,t}=\pi_i(\mathcal I_{i,t}),
]

FRIDS-v2 如何逼近该可行边界？

这对应 **distributed scheduler**。

于是论文就有一个非常稳定的逻辑：

[
\boxed{
\text{Can it be done?}
\rightarrow
\text{How close can distributed execution get?}
}
]

这比：

> OTFS grid 怎么选？
>
> bit 怎么分？
>
> power 怎么分？
>
> owner 怎么选？
>
> token 怎么压？
>
> correlation 怎么处理？

高级得多，也收敛得多。

# 六、OTFS 现在应该怎么处理？不要删，但也不要再拿来“救论文”

G10/G11 不是白做。

它们其实给出了一个非常好的边界：

> OTFS DD 结构会显著改变 evidence 和可行性，因此物理模型不能忽略 OTFS；但在当前固定资源设计族内，重新选 DD grid 没有形成稳定的任务时延优化优势。

这个结论反而很漂亮。

因此论文里面 OTFS 的作用应该是：

[
\text{OTFS physics}
\rightarrow
g_{iq}
]

而不是

[
\text{OTFS optimizer}
\rightarrow
\text{新的主算法}.
]

也就是说：

**OTFS 是物理真实性来源，不是第二个优化主线。**

这样就不会回到最开始。

# 八、接下来真正应该投入精力的反而是三件“收口工作”

我建议现在把优化力度从 **横向增加模块** 转成 **纵向加深已有核心**。

### 第一：把 FRIDS 的理论链补完整

目前最值得补的不是新算法，而是：

[
\text{P-DIST}
\rightarrow
\text{relaxation}
\rightarrow
\text{dual}
\rightarrow
J_{iq}
\rightarrow
\text{mirror descent}
\rightarrow
\text{delay/feasibility gap}.
]

现在最大的理论缺口是：

> mirror-descent regret 是对 instantaneous relaxation 的，而最终指标是 sequential detection delay。

如果能建立一个合理条件下的桥：

[
R_T
\Longrightarrow
\Delta T_{\max}
]

哪怕只是 upper bound / asymptotic bound，这个价值都比再增加一个调度模块高很多。

------

### 第二：把可行性区域真正做扎实

不要优化 (Q/K)。

研究：

[
(K,Q,s,B_{\rm U2U},g)
]

变化下的：

[
\text{feasible}
/
\text{coordination-limited}
/
\text{communication-limited}
/
\text{sensing-limited}.
]

这是**理论边界**，不是换研究点。

------

### 第三：解除 toy-grade 质疑，但不顺便优化

当前文档自己承认：

- fixed owner；
- full mesh；
- static geometry；
- one weak target。

仍然比较理想化。

下一阶段可以做：

- 多弱目标；
- heterogeneous owner；
- bounded mobility；
- sparse/partial connectivity。

但原则是：

> **先测试 frozen FRIDS-v2 是否仍成立。**

不是一加 mobility 就做 mobility-aware FRIDS；

不是一加 sparse topology 就做 graph-FRIDS；

不是一加 multiple weak target 就做 difficulty-aware FRIDS。

只有 frozen algorithm 明显失效，并且 oracle 证明存在可恢复结构性 gap，才允许修改。

这才能真正防止“又绕回去”。
