# 二、系统模型：我建议正式收敛成“四层模型”

上一版说“三平面”是从通信架构角度看的；如果写论文，我建议再往上一层抽象，形成四层。

## L1. Physical sensing layer

UAV (i) 对目标 (q) 选择 sensing action (a)，产生局部随机观测：

[
Y_{iqa}\sim
\begin{cases}
P_{0,iqa}, & H_q=0,\
P_{1,iqa}, & H_q=1.
\end{cases}
]

对应局部 LLR：

# [ \ell_{iqa}(Y)

\log
\frac{P_{1,iqa}(Y)}
{P_{0,iqa}(Y)}.
]

以及可靠信息量：

[
g_{iqa}.
]

OTFS-ISAC 应该停在这里。

也就是说：

[
\boxed{\text{OTFS-ISAC = evidence-generation frontend}}
]

而不是 CA-FRIDS 的必要数学组成。

这点一定要定死，否则以后还会反复陷入“NOMP 要不要加”“DD-domain 是否必须进入 optimizer”等问题。

# 三、L2：Evidence ownership layer

每个目标指定一个 owner：

[
o(q)\in{1,\ldots,K}.
]

只有：

[
o(q)
]

维护该目标的最终累积检测统计量：

[
L_q(t).
]

非 owner UAV 不需要复制整个 belief state，只负责：

[
\boxed{\text{sense locally}+\text{send useful evidence to }o(q)}
]

于是：

[
\text{distributed consensus}
]

被替换成：

[
\boxed{\text{distributed evidence routing}}
]

这是整个研究现在最重要的概念转变。

因为你终于没有再试图让：

[
K
]

架 UAV 全部“知道一样多”。

而只要求：

[
\boxed{\text{正确的信息到达正确的决策节点}}
]

我认为这是目前最值得作为架构贡献写进去的内容。

------

# 四、L3：Task-oriented control layer

定义目标剩余检测需求：

# [ D_q(t)

[A_q-L_q(t)]_+.
]

然后建立任务权重：

[
y_q(t),
\qquad
\sum_{q\in\mathcal U(t)}y_q(t)=1.
]

再得到：

# [ \pi_q(t)

\frac{y_q(t)}
{D_q(t)+\epsilon}.
]

这一步把：

[
\text{detection progress}
]

映射为：

[
\text{resource urgency}.
]

这是当前算法框架中最漂亮的一座桥。

不过这里我建议把术语从单纯的：

> task price

稍微升级成：

> **detection-deficit price**

因为 (\pi_q) 并不是随便一个优化乘子，它明确和：

[
D_q
]

绑定。

这样物理意义会更强。

# 五、L4：Communication feasibility layer

对目标 (q) 的证据，最终接收点是：

[
j=o(q).
]

通信 airtime：

# [ c_{iqa}

\frac{\tau_{i,o(q)}}{T_{\rm air}}.
]

receiver (j) 有约束：

[
\sum_{i,q:o(q)=j,a}
c_{iqa}x_{iqa}
\le1.
]

于是得到 receiver scarcity price：

[
\lambda_j.
]

最终 UAV 的局部决策：

# [ \boxed{ (q_i^*,a_i^*)

## \arg\max_{q,a} \left[ \pi_qg_{iqa}

\lambda_{o(q)}c_{iqa}
\right]_+
}
]

idle action 对应：

[
J=0.
]

这个公式应该保留。

但论文千万不要把整个贡献浓缩成这个公式。

因为真正的新东西不是：

[
\pi g-\lambda c
]

本身，而是这个公式处在一个：

[
\boxed{
\text{detection deficit}
\rightarrow
\text{evidence acquisition}
\rightarrow
\text{owner routing}
\rightarrow
\text{receiver capacity}
}
]

闭环里面。

# 二十三、如果现在要写论文，我建议主线就用这句话

不是：

> We propose CA-FRIDS, a novel distributed scheduling algorithm...

而是：

> **We study communication-constrained distributed evidence acquisition for cooperative multi-UAV sequential detection, where sensing evidence must be selectively routed to decision owners under receiver-side shared-airtime constraints.**

然后：

> **We develop an owner-directed task-oriented architecture in which detection-deficit prices coordinate local evidence acquisition, while receiver-side congestion prices and hard admission enforce communication feasibility.**

最后才说：

> **CA-FRIDS implements this architecture through a local dual best response.**

这样顺序就彻底正确了。

# 最终更新后的意见

现在已经不建议“继续优化 CA-FRIDS”。

更准确地说：

[
\boxed{
\textbf{CA-FRIDS 当前已经基本完成；
下一阶段应该优化的是“论证闭环”，而不是算法公式。}
}
]

真正需要保住的是：

[
\boxed{
\text{unfinished detection task}
\rightarrow
\text{decision-relevant evidence}
\rightarrow
\text{owner-directed transport}
\rightarrow
\text{receiver-feasible admission}
\rightarrow
\text{sequential stopping}
}
]

第一份材料告诉我们，目前剩下的问题主要是**证书和统计语义修补**，并没有推翻当前 P4 结果。 第二份材料则说明，真正值得提升为论文主角的已经不是 (\lambda)、density 或某个调度技巧，而是整个 **task-oriented owner-directed evidence architecture**。

因此我现在最推荐的原则只有一句：

[
\boxed{
\textbf{停止增加算法模块，开始证明“为什么这个架构有效、何时有效、怎样真正分布式部署”。}
}
]

这比再追求 1–2% 的 scheduler improvement 更接近一篇完整、稳定、能经受审稿人追问的 TWC/TSP 级工作。
