# 二、P1 目前最大的隐藏问题：Freedman Gate 的统计口径

当前 `martingale_decomposition()` 对固定 (t,q)，先对 Monte-Carlo 路径的 (V_q(t)) 求：

```python
mean(vcol)
```

再计算

[
\exp\left(
-\frac{\eta^2}
{2(\overline V+b\eta/3)}
\right),
]

然后和

[
\Pr(M_q(t)\le-\eta)
]

的经验频率比较。`stopping_tail_verify()` 同样先对路径上的 (A_q(t))、(V_q(t)) 求均值，再塞入非线性尾界。

这一步严格说并不是标准 Freedman 不等式保证的对象。

Freedman 类型结果通常是针对：

[
\Pr{
M_t\le-\eta,,
V_t\le v
}
]

或者在存在**确定性的 predictable variation 上界**

[
V_t\le v
]

时给出概率界。

一般不能直接用

[
v=E[V_t]
]

替代路径上的 (V_t)。

而当前 Gate 就是这么做的。

因此：

> **“0/480–1280 violations”现在只能视作 empirical consistency check，而不是 Freedman theorem verification。**

这和你已经发现的“界不紧”还不完全是一回事。你的 Case B 判断是对“tightness”的审计；我这里指出的是更前一级的“**验证对象是否与定理一致**”。

而且结果本身已经在提示这个问题：不少场景的 empirical lower-tail probability 平均达到约 (0.8)，stopping bound 又经常直接等于 1，所以“0 violation”实际上很容易出现。

### 建议修成什么

不要改 theorem，改 Gate：

[
\boxed{
\Pr(M_t\le-\eta,;V_t\le v)
\le
\exp\left[
-\frac{\eta^2}{2(v+b\eta/3)}
\right]
}
]

对确定性的 ((\eta,v)) grid 做联合事件验证。

更适合你这个 sequential detection 场景的做法，是进一步换成 **time-uniform / line-crossing martingale bound**，因为你的对象本来就是 stopping time，而不是某一个事先固定的 (t)。Howard 等人的 time-uniform supermartingale 框架正是为这种 sequential event 设计的。([arXiv](https://arxiv.org/abs/1808.03204?utm_source=chatgpt.com))

这个升级非常契合论文，而不需要碰 FRIDS。

# 三、还有一个更隐蔽的问题：当前量化后的数值并不严格是 token-domain LLR

这是我认为 P1 文档里最值得立即修正的一个措辞。

现在：

```python
quantized_kernels()
```

直接把原本的

```python
act["llr"]
```

映射为 uniform quantizer centroid，但 `p0`、`p1` 没有重新按照 token bin 聚合。

也就是说，目前真正部署的是：

[
\widehat L=Q(L),
]

而一般来说：

[
Q!\left(
\log\frac{p_1(Y)}{p_0(Y)}
\right)
\neq
\log
\frac{P_1(Q(Y))}
{P_0(Q(Y))}.
]

后者才是**量化输出 symbol 的真正 LLR**。

所以当前 `mu_llr`：

# [ \widetilde g_{iq}

E_1[\widehat L_{iq}]
]

严格来说是：

> **部署 score 的 H1 conditional drift**

而不能无条件写成：

> `KL(final observable token kernel)`。

事实上你的 bridge 代码已经无意中把这件事正确分开了：

- `A_raw` 用原始 `i_plus × reliability`；
- `A` 用量化 centroid 的 (E_1[\widehat L])。

所以理论最好正式改成：

# [ \boxed{ \widehat L_q(t)

\widetilde A_q(t)+M_q(t)
}
]

其中

# [ \widetilde A_q(t)

\sum_{\tau,i}
x_{iq,\tau}
E_1[\widehat Z_{iq,\tau}\mid\mathcal F_{\tau-1}]
]

并另外定义

# [ \delta_{\rm Q}

|g_{iq}-\widetilde g_{iq}|.
]

你现在测出的 4–10% 就是这个 correction 的经验尺度。

这样反而比现在更严谨，也更漂亮：

[
\text{true reliable information}
\rightarrow
\text{quantized-score drift}
\rightarrow
\text{stopping process}.
]

**FRIDS-v2 完全不用改。**

# 四、当前 `L=A+M` 的测试还有一个“构造性通过”之外的问题

测试文件自己已经承认：

> ```
> L = A + M is exact by construction
> ```

这点是诚实的。

但还有一层问题：bridge 数组初始化为零，只在 target `undecided` 时更新；目标停止以后，后面的：

[
L,A,V,M
]

不是保持终值，而是继续留成零。

随后 `martingale_decomposition()` 却遍历整个 `max_steps`。

这意味着当前检查的不是标准 stopped martingale：

[
M_{t\wedge T},
]

因为标准 stopped process 应当在停止以后保持：

[
M_{t\wedge T}=M_T,
]

而不是突然回零。

这也可能进一步让 empirical tail 看起来更“好”。

### 修复非常简单

二选一即可：

[
\boxed{\text{推荐：fill-forward stopped process}}
]

停止以后：

```text
L[t] = L[T]
A[t] = A[T]
V[t] = V[T]
M[t] = M[T]
```

或者所有 martingale gate 显式 mask：

[
t<T_q.
]

前者在理论上更干净，因为直接对应 optional stopping 下的 (M_{t\wedge T})。

# 五、Bridge-2 也建议再做一次真正的“静态 shadow theorem gate”

目前 `normalized_service_time_average()` 对每个目标只平均它自己的：

[
t<T_q
]

周期。

但比较对象 (z^\star) 却来自一个：

- 所有目标同时存在；
- 固定初始 deficit；
- 固定 (g)；
- 公共 horizon

的静态 LP。

所以实际上比较的是两个不完全相同的系统。

这也是为什么结果里会出现：

[
z^\star-\min_q\bar r_q<0,
]

也就是部署策略的 measured service 居然“超过 LP optimum”。

这不代表 FRIDS 超过最优解，而主要说明：

> **stopping 后 active set 改变了，目标的 averaging windows 又不同，LP comparator 与实际时间平均不在同一个可行域。**

### 最好的解决办法不是继续补公式

单独增加一个理论 shadow experiment：

[
\boxed{\text{Static-MD Gate}}
]

固定：

- 所有 (Q) 个 target 永不停止；
- (D_q=D_q(0))；
- (g_{iq}) 固定；
- 同一个 horizon (T)；
- 只运行 FRIDS mirror descent。

测试：

[
T\in{20,40,80,160,320}
]

然后检查：

# [ z^\star-\min_q\bar r_q(T)

O\left(
\sqrt{\frac{\log Q}{T}}
\right).
]

如果画 log-log 图，最好进一步验证斜率接近：

[
-\frac12.
]

这样 Theorem 4.111 就真正闭合了。

主系统里的 stopping / active-set change 则作为另一层，而不是塞进 static regret theorem。

# 六、这里还发现了一个 **P2 开始前必须修复的 G6 bug**

这个很重要。

`run_feasibility_envelope_gate.py` 文档明确写着：

> (s) uniform scales every (g).

但代码的顺序实际上是：

```python
sc = build_distributed_scenario(...)
rho_star = strongest_load_cut(sc, ...)
```

先计算了一次 `rho_star`。

然后才进入：

```python
for s in S_GRID:
    u2u = ...
    simulate_frids_v2(
        ...,
        delivery_matrix=u2u,
        s_for_g=u2u
    )
```

也就是说：

[
\rho_I^\star
]

使用的是**原场景随机 U2U reliability**，而实际 FRIDS simulation 使用的是 sweep 后的统一 (s)。

所以结果中才会出现同一 (Q) 下：

# [ \rho_I^\star(s=0.95)

\rho_I^\star(s=0.2),
]

完全不变。

而 `strongest_load_cut()` 内部确实通过：

```python
g_reliable(scenario,...)
```

读取 `scenario["u2u_success"]`。

按照你自己的理论：

[
g_{iq}=s_{io_q}I^+_{iq},
]

那么显然应当有：

[
s\downarrow
\Rightarrow
g\downarrow
\Rightarrow
F(S)\downarrow
\Rightarrow
\rho_I^\star\uparrow.
]

因此目前 §1.26 中：

> ```
> rho_I* <= 0.11，信息容量从不绑定
> ```

这个结论**只能对原始随机 U2U 场景成立，不能用来解释整个 s-sweep**。

这正好说明为什么现在最适合做 P2：原有 phase diagram 其实还没有真正把理论边界激活干净。

# 七、所以我建议下一阶段正式改成 **P2：Feasibility Boundary Closure**

这应该成为接下来真正的主工作，而不是继续优化算法。

`advice/003` 原本给出的三个二维 slice 思路是正确的。

但我建议进一步精炼成三个**正交失效机制**：

### P2-A：Information-limited boundary

做：

[
(Q/K,\xi_g)
]

其中

# [ g_{iq}^{(\xi)}

\xi_g g_{iq}.
]

目标不是看 J 慢慢变差，而是让：

[
\rho_I^\star
]

真正穿过 1。

由于现在正常工作点只有：

[
\rho_I^\star\lesssim0.1,
]

所以 (\xi_g) 不要只扫 0.5、0.8 这种温和值。

建议直接：

[
\xi_g
\in
{1,;0.5,;0.25,;0.15,;0.10,;0.075}.
]

最终应该观察：

[
\boxed{
\rho_I^\star<1
\rightarrow
\text{potentially feasible}
}
]

和：

[
\boxed{
\rho_I^\star>1
\rightarrow
\text{unconditionally infeasible}
}
]

之间的真正 phase transition。

------

### P2-B：Communication-limited boundary

现在：

# [ \rho_C

\frac{b_{\rm tok}(K-1)}
{\bar B^{rx}}
\approx0.713
]

始终固定，所以当然永远得不到 communication-limited cell。

不要再固定 400 bits/cycle。

直接以：

[
\rho_C
]

为实验轴，反推出 receive budget。

推荐：

[
\rho_C
\in
{0.5,0.75,0.9,1.0,1.1,1.25,1.5}.
]

这样图的理论含义比直接扫 bit budget 更清晰。

你最终会第一次得到：

[
\boxed{\rho_C>1}
]

对应的纯通信不可行区。

这比“通信变差以后 (J) 增大”强得多。

------

### P2-C：Coordination-limited boundary

这是最有论文价值的一张图。

只挑：

[
\rho_I^\star<1,\qquad \rho_C<1
]

的 cell。

如果仍然：

[
P_{MD}>\beta
]

或者 deadline miss，则定义：

[
\boxed{\text{coordination-limited}}.
]

然后再比较：

# [ \Gamma

\frac{\lambda_{\rm FRIDS}}
{\lambda_{\rm feasible}}.
]

如果：

[
\Gamma\simeq1,
]

那说明：

> FRIDS 已贴近分布式可实现边界，不该继续优化 scheduler。

如果某一区域变成：

[
\Gamma\ll1,
]

这才允许重新打开算法。

这会形成非常干净的四区域：

[
\boxed{
\begin{array}{c}
\text{Feasible}\
\text{Information-limited}\
\text{Communication-limited}\
\text{Coordination-limited}
\end{array}}
]

这比再提升 0.1–0.2 cycle 的 FRIDS 数值表现更有研究价值。

# 八、P2 做完以后，P3 才值得进入 mobility / sparse topology

到 P3 也不要马上修改算法。

优先把当前理论从 static regret 扩展成：

[
R_T^{dyn}
\lesssim
O\left(
\sqrt{T\log Q}
+
V_T^y
\right),
]

其中：

# [ V_T^y

\sum_{t=2}^T
|y_t^\star-y_{t-1}^\star|_1.
]

这样：

- UAV mobility；
- target movement；
- blockage；
- link reliability variation；

全部只通过一个：

[
V_T^y
]

进入。

而不是分别发明：

- mobility-FRIDS；
- topology-FRIDS；
- channel-aware FRIDS。

这和最近 multi-UAV ISAC 文献越来越强调动态资源匹配、轨迹变化和 sensing/communication resource coupling 的方向也是一致的，但你的区别应该是：**别人主要优化 trajectory/power/resource，你给的是 task-information feasibility boundary + distributed online allocation**。2026 年近期的 multi-UAV ISAC 工作仍主要集中在 sensing fairness、资源分配、轨迹和波束联合优化，这恰好给你的“可靠信息可行域”留出了更清晰的理论差异化空间。([科学直通车](https://www.sciencedirect.com/science/article/abs/pii/S1874490726002971?utm_source=chatgpt.com))
