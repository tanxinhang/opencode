## 1. P4.1 主体通过，但发现一个新的 P0：v2 neutral admission 的随机优先级被“冻结了一整局”

FRIDS-v2 的 airtime 路径在每个 cycle 内执行：

```python
policy_rng = np.random.default_rng([seed, r, 9021])
tie_keys = policy_rng.random(k)
```

问题是 seed 中**没有 `t`**。因此对于固定 episode `r`，每个 cycle 都重新初始化成同一个 RNG，于是得到**完全相同的 `tie_keys`**。换句话说：

# [ \pi_{i}^{(r,1)}

\pi_{i}^{(r,2)}
=\cdots=
\pi_{i}^{(r,T)}.
]

而 CA-FRIDS 在 CRN 模式下用的是持续推进的 `rng_r.random(k)`，每周期会产生新的 admission tie keys。

这个问题在非拥塞区没有影响，因为所有 offer 都被 admission；但在 congested 区非常关键。正式结果里 v2 每 UAV 每周期有 **15 个 offer**，却只有大约 **8.2 个 admitted**。

于是目前实际上可能发生：

[
\boxed{
\text{某些 UAV 在一个 episode 内持续获得高 admission 优先级，
另一些 UAV 持续被压制}
}
]

特别是 v2 又是 full-mesh broadcast，同一个 `tie_keys[src]` 还被用于多个 receiver。这会产生**persistent source favoritism**。

这不是标签偏置——跨 episode 平均仍可能交换对称——但它是**时间维度上的不公平性**。对于 sequential detection，持续几十帧压制同一组高质量传感器，完全可能显著增加 stopping delay。

因此现在的：

[
+25.4%
]

我认为是**可信的候选结果，但还不能最终冻结为论文主数字**。

## 2. 修复很小：不要改算法，只把 policy randomness 语义真正冻结

建议建立独立的：

[
U_{\rm policy}[r,t,j,i],
]

分别对应 episode、cycle、receiver、source。

然后：

# [ \text{neutral priority}_{ij}(t)

U_{\rm policy}[r,t,j,i].
]

A/B 两个 neutral admission arm 必须共享同一 policy tape。

这样同时得到：

[
\text{temporal exchangeability}
+
\text{receiver exchangeability}
+
\text{label equivariance}.
]

而且它必须与物理 CRN：

[
U_H,U_{\rm obs},U_{\rm link}
]

分开，因为 admission tie-breaking 是**算法随机性**，不是外生物理随机性。

我还建议让 `airtime_admit(policy="neutral")` 在没有 `tie_keys` 时**直接报错**。当前实现没有 key 时最终会使用 `src_uav` 作为排序项，因此 primitive 自己声称的“exchangeable neutral”在一般调用下并不成立。

# 3. 第二个重要发现：当前“三臂消融”不能严格叫 `Δ_steering`

这个问题甚至比 density admission 本身更值得纠正措辞。

当前三臂：

| Arm  | sensing/task scheduler | evidence topology | admission |
| ---- | ---------------------- | ----------------- | --------- |
| A    | FRIDS-v2               | **full mesh**     | neutral   |
| B    | CA                     | **owner-only**    | neutral   |
| C    | CA                     | owner-only        | density   |

实际数据非常明显：

[
\text{v2 offers/UAV/cycle}=15,
]

而 CA 只有约：

[
0.82\sim0.93.
]

这是因为 CA 代码明确：

> 每个 sensing UAV 只向 target owner 发一个 evidence offer，并且还有 idle gate。

所以现在

[
J_{\rm CA,neutral}-J_{\rm v2,neutral}
=-1.535
]

**并没有只改变 congestion-price steering**。

它同时改变了：

[
\boxed{
\text{task steering}
+
\text{airtime price}
+
\text{idle gating}
+
\text{full-mesh}\rightarrow\text{owner-only routing}
+
\text{belief architecture}
}
]

因此当前最严谨的名称应该从：

[
\Delta_{\rm steering}
]

改成例如：

[
\boxed{
\Delta_{\rm CA-preAdmission}
}
]

或者：

> CA architecture gain before density admission.

但：

# [ \Delta_{\rm admission}

J_{\rm CA,density}-J_{\rm CA,neutral}
]

这个因果解释是基本干净的，因为 B/C 只改变 admission priority。

所以目前真正能下的结论是：

> **CA 的大部分收益发生在 density admission 之前；density packing 的额外贡献很小。**

而暂时不能写：

> **25.4% 的收益几乎全部来自 congestion-price steering。**

# 6. 一个更深的理论残差：Freedman/delay bridge 在拥塞模式下已经不再“exact”

这个问题现在**不阻塞 P4.1 性能结果**，但会影响论文里的理论证书。

`simulate_frids_v2` 的 bridge 仍把：

[
s_{i,o(q)}
]

即物理 link success probability，当成 deliverable increment 的可靠性。

但 P4.1 以后真正的 cross-UAV increment 是：

# [ Z_{iq}(t)

I_{\rm adm}(i,o(q),t)
I_{\rm link}(i,o(q),t)
X_{iq}(t).
]

因此在 congestion 下：

[
\mathbb E[Z_{iq}(t)\mid\mathcal F_t]
\neq
s_{i,o(q)}\mu_{iq}
]

一般应该是：

# [ \mathbb E[Z_{iq}(t)\mid\mathcal F_t]

p^{\rm adm}*{iq}(t)
s*{i,o(q)}
\mu_{iq},
]

或者如果把已经实现的 admission decision 纳入 filtration：

# [

I_{\rm adm}(t)
s_{i,o(q)}
\mu_{iq}.
]

现在 bridge 的代码仍然按纯 link reliability 建 `rel_mat` 和 predictable variance，因此所谓“exact quantized-domain conditional mean”在**uncongested** 情形仍成立，在**binding airtime admission** 下则不能直接这样宣称。

这个很好修：记录每周期 owner-directed `admission_mask`，然后用它构造 (A_t,V_t)。

建议不要现在扩理论，只做这一处语义修复。

# 7. P4.2 的方向没问题，但一定要用真正的 anytime-valid 统计

很好，而且正好可以利用当前：

[

构造：

[
25\rightarrow50\rightarrow100\rightarrow200
]

个 nested MC blocks。

但是**不能在四次 look 上反复使用普通 95% Clopper–Pearson，然后看到 PASS 就停**。那会产生 optional-stopping coverage 问题。

正确目标应该是：

[
\Pr\left(
\forall n,\forall q:
p_{FA,q}\in C_{FA,q}(n),
;
p_{MD,q}\in C_{MD,q}(n)
\right)
\ge0.95.
]

Howard、Ramdas 等人的 confidence-sequence 框架正是为这种 repeated monitoring / data-dependent stopping 设计的。([IMStat](https://www.imstat.org/publications/aos/aos_49_2/aos_49_2.pdf?utm_source=chatgpt.com))

Gate 定义保持极简单：

[
\boxed{
PASS:
\max_q U_{FA,q}\le\alpha
;\land;
\max_q U_{MD,q}\le\beta
}
]

[
\boxed{
FAIL:
\exists q:
L_{FA,q}>\alpha
;\lor;
L_{MD,q}>\beta
}
]

否则继续取样；60k 仍 unresolved 就保持 UNCERTAIN。

如果不想实现完整 mixture CS，也可以采用**预注册四阶段 alpha-spending + one-sided exact binomial bounds**；虽然更保守，却比重复普通 CP 严格得多。

每个 stage 必须保存：

[
N_{H0,q},N_{H1,q},N_{FA,q},N_{MD,q},
]

并同时保存 incremental counts、cumulative counts、seed range、CS bounds、decision、stopping stage 和 provenance。

# 8. expected-(P_D) primal-dual：这里需要提前纠正一个数学形式

我不建议后面直接使用类似：

[
\Delta_q(a|S)+y_q+\nu_o
]

这种加法 score。

如果定义：

# [ F_q(S_q)

\mathbb E[P_{D,q}(S_q)]
]

并考虑 max-min sensing utility：

[
\max z
]

s.t.

[
F_q(S_q)\ge z,\qquad\forall q,
]

以及 receiver airtime：

[
\sum_{a:o(a)=j}c_a x_a\le1,
]

那么 Lagrangian 应为：

[
\mathcal L=
z+
\sum_q y_q(F_q-z)
+
\sum_j\lambda_j
\left(
1-\sum_{a:o(a)=j}c_a x_a
\right).
]

由：

[
\sum_q y_q=1
]

得到单个 candidate 的边际 best response：

# [ \boxed{ J_{iqa}

## y_q \Delta_q(a\mid S_q)

\lambda_{o(q)}c_{iqa}.
}
]

如果还显式 dualize UAV 自身：

[
\sum_{qa}x_{iqa}\le1,
]

才进一步得到：

# [ \boxed{ J_{iqa}

y_q\Delta_q(a|S_q)
-\lambda_{o(q)}c_{iqa}
-\nu_i.
}
]

所以：

- (y_q) 是**乘在 semantic marginal gain 上的 task dual weight**；
- (\lambda_j) 是 receiver scarcity price，所以必须**减掉通信成本**；
- (\nu_i) 如果存在，也是 resource price，通常也是减号。

这个结构比简单的 `Δ+y+ν` 数学上干净得多。

# 9. 但 expected-(P_D) 还有一个比算法形式更重要的问题：不要把研究目标又换掉

你当前正式 Gate 优化的是：

[
\boxed{
\max_q
\mathbb E[T_q\mid H_1]
}
]

且受 (P_{FA},P_{MD}) QoS 约束。

而当前 `expected_pd.py` 定义的是一个**静态 report-set utility**：

[
F_q(S)=\mathbb E[P_D(S)].
]

两者并不自动等价。

如果直接把静态 (\Delta P_D) 塞进当前 sequential CA，很容易再次出现：

> 数学上优化了一个漂亮的新目标，但论文主 Gate 测的是另一个目标。

所以我建议 expected-(P_D) 先作为**challenger**，不要直接替代目前的 (g/(D+\epsilon))。

更强、更贴合当前系统的最终升级其实是：

[
\boxed{
\text{Stopping-Aware Semantic Marginal}
}
]

即基于当前 owner LLR (\ell_q(t)) 和剩余 horizon：

# [ \Delta_{q,t}^{\rm stop}(a)

## \mathbb E \left[ V_q^{t+1}(\ell_q+Z_a) \right]

V_q^{t+1}(\ell_q),
]

其中 (V_q^t(\ell)) 可以定义为剩余 horizon 内正确完成 sequential decision 的概率或负的 remaining stopping time。

由于当前 LLR 是量化后的有限状态，一维 target-level DP 实际上并不离谱。这会把：

[
\text{detection semantics}
\rightarrow
\text{sequential stopping}
\rightarrow
\text{communication congestion price}
]

真正连成一条理论链。
