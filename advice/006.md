# 一、P2 smoke 的主要结论成立，但要收紧两句话

P2-A2 确实证明了一个很有价值的事实：物理降低 SNR 后，真实 (p_0,p_1,\mathrm{LLR},I^+) 都被重新生成，而不是人为改 scheduler 的 (g)。结果从 0 dB 的 (\rho_I^\star=0.0327)，发展到 −14 dB 的 (3.253)，所以真实物理链确实能够让 information cut 穿过 1。

P2-B 也至少完成了“通信负载不再只是表格标签”：(\rho_C=1.2,1.5) 时 survival 分别降为 (0.833,0.667)，并实际送进 `delivery_matrix` 与 `s_for_g`。

但两句话需要改：

> “−6 dB detector 本身失效”

目前最多应叫：

> **frozen two-threshold calibration family becomes infeasible on the audited calibration grid**

因为 `calibrate_target_bounds()` 搜索的是 Wald 阈值附近有限的 ((A,B)) grid；`ValueError` 的精确定义是“该搜索网格没有找到满足 (P_{FA},P_{MD}) 的阈值”，并不是“所有检测器从信息论上都不可能”。

另外：

> “(\Gamma=1\Rightarrow) FRIDS 无算法 gap”

目前也不能成立。这个需要重点修正。

# 二、当前 P2-C 的 (\Gamma=1) 实际是一个 **right-censored result**

现在只扫：

[
Q\in{4,8,12,16},
\qquad K=16.
]

最后得到：

# [ \lambda_{\rm FRIDS}

# \lambda_{\rm common}

# \lambda_{\rm nec}

1. 

]

问题在于三者**全部正好等于扫描上界** (Q/K=1)。

所以当前真正证明的是：

[
\boxed{
\lambda_F,\lambda_C,\lambda_{\rm nec}\ge1
}
]

而不是：

[
\lambda_F=\lambda_C=\lambda_{\rm nec}.
]

换句话说，边界根本还没有被找到。

因此当前：

[
\Gamma_{\rm alg}=1
]

应该标：

> **censored at tested load ceiling**

而不能标“无算法 gap”。

这不会导致 FRIDS 解冻。只是 P2-C 尚未真正测到容量边界。

# 三、更重要的是，`common` 也不是完整 coordination oracle

`price_mode="common"` 的代码定义非常明确：

- 使用 (y_{\rm common})；
- 但是仍保留每架 UAV 自己的 (D_{\rm loc}^{(i)})；
- 其他局部信息结构都不变。

也就是说动作仍是：

# [ q_i^\star

\arg\max_q
\frac{
y_q^{\rm common}g_{iq}
}{
D_{iq}^{\rm loc}+\epsilon
}.
]

因此它准确测量的是：

[
\boxed{\text{local dual-price disagreement loss}}
]

而不是所有：

[
\boxed{\text{distributed coordination loss}}.
]

所以我建议正式 P2 不再叫：

# [ \Gamma_{\rm alg}

\frac{\lambda_{\rm FRIDS}}{\lambda_{\rm common}},
]

而先改名为：

# [ \boxed{ \Gamma_{\rm dual}

\frac{\lambda_{\rm local}}
{\lambda_{\rm common-price}}
}
]

如果它接近 1，只能说：

> local price disagreement is not capacity-limiting.

这个结论已经足以支持继续冻结 FRIDS。

不要为了制造“algorithm oracle”现在又开发一大套中央算法。

[

分离。

# 五、Q sweep 现在还存在一个容易污染 (\lambda) 的问题：场景不是 nested workload

当前 P2-C 对每个 Q 都重新：

```python
build_distributed_scenario(rng(0), q_targets=q)
```

。

因为随机数是在：

[
(i,q)
]

循环里依次消耗的，Q 改变以后，后续 UAV 对应的随机 realization 也会改变。

因此：

[
Q=8
]

和：

[
Q=12
]

不是“同一个场景里增加了 4 个 target”，而是部分 channel/kernel realization 也发生了变化。

这样得到的：

[
\lambda=\max Q/K
]

同时混入了：

[
\text{load change}
+
\text{scenario redraw}.
]

正式 P2 必须改成 **nested-Q**：

先生成：

[
Q_{\max}
]

完整场景，例如 64 个 target，然后构造：

[
\mathcal Q_4
\subset
\mathcal Q_8
\subset
\mathcal Q_{12}
\subset\cdots
\subset
\mathcal Q_{64}.
]

这样有一个非常漂亮的性质：

[
Q_1<Q_2
\Rightarrow
\rho_I^\star(Q_1)
\le
\rho_I^\star(Q_2),
]

因为原来的 subset cuts 仍然存在。

这会让容量边界干净很多。

# 六、P2-B 目前是“平均意义 admission”，还不是 hard receive budget

现在实现：

# [ s_{ij}^{\rm eff}

s_{ij}^{phy}
\min\left(
1,\frac{B_{rx}}{b_{\rm tok}N_{\rm offered}}
\right),
]

然后 simulator 对每条 link 独立 Bernoulli delivery。

它保证的是**平均 survival**正确。

但一个具体 cycle 内仍可能接收超过：

[
B_{rx}
]

允许的 token 数。

因此正式 P2-B 如果要声称：

> hard communication-budget boundary

建议真正实施：

[
\boxed{
\sum_{j\neq i}
b_{\rm tok}z_{ji,t}
\le B_i^{rx}
}
]

逐 receiver、逐 cycle admission。

最干净的中性方案是不引入新调度策略：

设

[
m_i=
\left\lfloor
\frac{B_i^{rx}}
{b_{\rm tok}}
\right\rfloor.
]

若收到 (n_i>m_i) 个 offered packets，则随机无放回保留 (m_i) 个。

若预算有小数部分：

[
\theta_i=
\frac{B_i^{rx}}{b_{\rm tok}}-m_i,
]

则以概率 (\theta_i) 多允许一个。

于是：

# [ E[N_i^{adm}]

\frac{B_i^{rx}}{b_{\rm tok}},
]

同时又满足 pathwise hard budget。

这样才是真正的：

[
\rho_C>1
\rightarrow
\text{resource contention}
\rightarrow
\text{token loss}
\rightarrow
g^{eff}
\rightarrow
T_q.
]

FRIDS 不需要改。

# 七、还有一个小但必须修的 QoS 判据：目前正式判断基本只检查 `P_MD`

例如：

```python
qos_feasible_q(...)
```

最终只判断：

```python
p_md_max <= beta + 0.02
```

而没有同时检查 (P_{FA})。

正式 phase diagram 应统一成：

[
\boxed{
P_{MD,q}\le\beta,\qquad
P_{FA,q}\le\alpha,\quad\forall q.
}
]

而且 multi-seed 后不要直接用点估计硬分类。

最好用：

[
UCB(P_{MD,q})\le\beta+\delta,
]

[
UCB(P_{FA,q})\le\alpha+\delta.
]

于是可以诚实产生三种统计状态：

- **PASS**
- **FAIL**
- **UNCERTAIN**

边界附近的 UNCERTAIN cell 再增加 MC，而不是整个网格全部暴力加到 1000/5000 runs。

# 八、P2-A2 的意外结果其实提示了一个更好的正式相图设计

你现在发现：

[
-6\text{ dB}
]

时 calibration family 就已经失败，

而：

[
\rho_I^\star>1
]

直到约 −14 dB 才出现。

这说明仅靠“疯狂降低 SNR”寻找 information-limited region，会先撞上 local detection front-end/policy-family boundary。

这不是坏结果，反而非常重要。

因此正式相图不要只画：

[
(Q/K,\mathrm{SNR}).
]

建议最终使用两层表达。

第一层是物理生成参数：

[
(Q/K,\ \mathrm{SNR}),
\qquad
(Q/K,\ \rho_C).
]

第二层才是统一的 normalized feasibility plane：

[
\boxed{
(\rho_I^{pre},\rho_C)
}
]

其中：

[
\rho_I^{pre}
]

使用**通信预算 drop 之前**的可靠物理链路质量。

另外记录：

[
\rho_I^{eff}
]

作为 overload 后的有效信息负载。

这样通信过载导致：

[
s^{eff}\downarrow
\Rightarrow
\rho_I^{eff}\uparrow
]

时，不会错误地把一个 communication-caused failure 又标成 information-caused failure。

# 九、最终区域建议从原来的四类升级成“4+1”

不是扩展研究问题，而是把因果口径分开：

| 条件                                                    | 区域                                       |
| ------------------------------------------------------- | ------------------------------------------ |
| frozen detector/calibration family 无法取得可靠可行证书 | **Detection-policy limited / uncertified** |
| detector feasible，(\rho_I^{pre}>1,\rho_C\le1)          | **Information-limited**                    |
| (\rho_I^{pre}\le1,\rho_C>1)                             | **Communication-limited**                  |
| 两个 necessary condition 都满足，但 FRIDS QoS fail      | **Coordination-limited**                   |
| 两个条件满足且 QoS pass                                 | **Feasible**                               |

如果：

[
\rho_I^{pre}>1,\quad\rho_C>1,
]

单独标：

> mixed I+C infeasible

即可。

这里我刻意没有把目前 −6 dB 直接定性为“Detection-limited”，因为现阶段只能证明 calibration grid infeasible。

# 十、P2-C 建议这样重构，仍然不新增算法

至少把 Q 扫描扩到真正出现失败：

[
Q=
{4,8,12,16,24,32,48,64,\ldots}.
]

一旦 bracket 到边界，再局部补整数 Q。

并且每个 Q 都重新检查：

[
\rho_I^\star(Q)<1,
]

以及：

# [ \rho_C(Q)

\frac{b_{\rm tok}(Q)(K-1)}
{B_{rx}}
<1.
]

因为 `token_bits(Q)` 本身可能随 Q 增长，所以不能只用 Q=8 的 (\rho_C) 证明整个 Q sweep 都是 doubly feasible。

然后定义：

# [ \lambda_F

\max\left{
Q/K:
\text{FRIDS statistically feasible}
\right},
]

# [ \lambda_C

\max\left{
Q/K:
\text{common-price audit feasible}
\right},
]

# [ \lambda_{nec}

\max\left{
Q/K:
\rho_I^\star\le1,\rho_C\le1
\right}.
]

先只报告：

# [ \boxed{ \Gamma_{\rm dual}

\lambda_F/\lambda_C
}
]

和：

# [ \boxed{ \Gamma_{\rm envelope}

\lambda_F/\lambda_{nec}.
}
]

不要再直接叫 (\Gamma_{\rm alg})。

# 十一、A1 其实已经不值得继续跑了，它可以直接变成解析 sanity check

因为 A1 对所有 (g) 同比例乘：

# [ g_{iq}^{(\xi)}

\xi g_{iq},
]

所以：

# [ F_\xi(S)

\xi F(S).
]

因此：

# [ \rho_I(S;\xi)

\frac1{\xi}\rho_I(S;1),
]

最终：

# [ \boxed{ \rho_I^\star(\xi)

\frac{\rho_I^\star(1)}{\xi}.
}
]

你现在的数据完全符合这个关系，例如：

# [ 0.03273/0.075

0.4364.
]

因此 P2-A1 不需要正式 multi-seed。

把它降级成：

> analytic unit consistency check.

正式计算资源全部投入 A2/B/C。

这会让研究更收敛。

# 十二、我建议下一步只做一个 P2.1，而不是继续“优化算法”

具体顺序：

1. **冻结 P1，禁止再修改。**
2. 修 formal phase runner：
   - 真正使用 scenario seed × MC seed；
   - nested-Q workload；
   - (P_{MD}+P_{FA}) 双 QoS；
   - hard receiver admission；
   - `Gamma_alg` 改 `Gamma_dual`；
   - Q sweep 必须真正 bracket capacity；
   - calibration failure 改成 `calibration-family-infeasible`，除非另有充分证书。
3. 先跑很小的 formal coarse grid：
   [
   5\text{ scenario seeds}\times 300\text{ MC runs}.
   ]
4. 只对 boundary/uncertain cells追加：
   [
   10\text{ seeds}\times 1000\text{ runs}
   ]
   或自适应跑到 CI 足够窄。
5. 最终输出：
   - Information phase slice
   - Communication phase slice
   - unified ((\rho_I^{pre},\rho_C)) phase map
   - (\Gamma_{\rm dual}) / envelope utilization curve

这样比直接跑一个巨大矩阵更有效。

## 最终定位

目前最值得保留的主线已经非常明确：

[
\boxed{
\text{OTFS/physical sensing}
\rightarrow
I^+
\rightarrow
s^{phy}I^+
\rightarrow
\text{communication admission}
\rightarrow
g^{eff}
\rightarrow
\text{FRIDS allocation}
\rightarrow
T_q

然后回答三个问题：

[
\boxed{
\begin{aligned}
&\text{信息本身够不够？}\
&\text{网络搬得动吗？}\
&\text{若前两者都够，分布式协调损失多少？}
\end{aligned}}
]

这比继续优化 FRIDS 更有论文价值。

因此我对当前状态的最终判断是：

[
\boxed{\text{P1 permanently closed}}
]

[
\boxed{\text{FRIDS-v2 permanently frozen unless P2 finds >5% recoverable gap}}
]

[
\boxed{\text{P2 smoke passed mechanism-discovery gate}}
]

但还不能写：

[
\boxed{\Gamma=1\Rightarrow\text{no algorithm gap}}
]

当前最准确的是：

[
\boxed{
\text{no detected local-dual gap up to the tested censored load }Q/K=1.
}
]
