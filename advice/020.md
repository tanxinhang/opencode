# 二、最重要的新发现：当前 B0-lite 不是“严格等价重参数化”

这是本轮我认为优先级最高的问题。

最新代码明确声称 normalization-free B0-lite 是 λ-free B0 的 strict policy-equivalent reparameterization。实现是：

[
\ell_q=\log y_q-\mu r_q,
]

然后代码仍然执行

[
\ell_q\leftarrow
\ell_q-\max_p\ell_p,
\qquad
w_q=e^{\ell_q},
]

只是不再除以

[
Z=\sum_p w_p.
]

代码注释也明确声称这样“不再需要 global reduction”。

在**无限精度、不量化、(\lambda=0)** 的数学模型下，取消 (Z) 是完全正确的：

# [ \arg\max_q \frac{(w_q/Z)g_{iq}}{D_q+\epsilon}

\arg\max_q
\frac{w_qg_{iq}}{D_q+\epsilon}.
]

问题出在部署代码随后做了：

[
\pi_q=\frac{y_q}{D_q+\epsilon},
]

然后对 (\pi_q) 用固定绝对区间做有限 bit 均匀量化，再使用量化后的 `pi_b` 做实际 `score_b`。

而一般情况下：

[
Q(c x)\neq cQ(x).
]

所以：

[
\arg\max Q!\left(
\frac{w_q/Z}{D_q+\epsilon}
\right)g_{iq}
]

不保证等于

[
\arg\max Q!\left(
\frac{w_q}{D_q+\epsilon}
\right)g_{iq}.
]

特别是在量化 bin 边界、近并列 action 以及 idle gate 附近，这会直接改变动作。

这不是纯理论担忧。**P5-MIN 自己已经实证发现若干 cell 中 B0-lite 相对于 normalized B0 是 `CERTIFIED_LOSS`，并直接输出：**

> ```
> B0-lite is CERTIFIED slower than normalized B0 (norm-free is NOT a reparameterization here)
> ```

runner 本身也把这个作为 verdict FAIL 条件。

因此目前必须把：

> strict policy-equivalent reparameterization

改成：

> **exactly scale-equivalent before finite-rate control quantization; the deployed finite-bit implementation is an approximation whose action distortion must be certified.**

这个修改很重要。

# 三、而且现在实际上还没有消除 global reduction

虽然你删除了 (Z=\sum_qw_q)，但代码还有：

[
\ell_q\leftarrow\ell_q-\max_p\ell_p.
]

这个：

[
\max_p\ell_p
]

本身就是跨所有 active targets 的全局归约。

如果每个 target 的 owner 分散在不同 UAV 上，那么想得到全局 max 仍然需要：

[
\text{reduction / consensus / spanning-tree exchange}.
]

所以现在只能说：

> 去掉了 global **sum-normalizer (Z)**。

还不能说：

> 去掉了所有 global reduction。

### 真正的 normalization-free 形式

反而可以把算法进一步简化得更干净。

每个 owner 独立维护：

# [ \boxed{ \theta_q(t+1)

\theta_q(t)-\mu r_q(t)
}
]

根本不做 max-shift，也不做 sum normalization。

当 (\lambda=0) 时，各 UAV 直接比较：

# [ \boxed{ s_{iq}

\theta_q
+\log g_{iq}
-\log(D_q+\epsilon)
}
]

于是：

[
q_i^\star=\arg\max_q s_{iq}.
]

这样：

- 不需要 (Z)；
- 不需要 global max；
- 不需要 global average；
- 每个 owner 只广播自己的 (\theta_q) 或 (\Delta\theta_q)；
- UAV 本地完成 argmax。

这才是真正意义上的：

[
\boxed{\text{Normalization-Free Distributed Deficit Pricing}}
]

而且数学上比现在的 `w=max-centered exp(theta)` 更干净。

有限 bit 时，也应该量化：

[
\theta_q
\quad\text{或}\quad
\Delta\theta_q=-\mu r_q,
]

而不是量化一个随任意公共尺度变化的 (\pi_q)。

这样“取消 normalization”与“有限比特控制”才真正兼容。

# 五、关键混杂来自 `T_air` 的构造方式

`build_airtime_model()` 当前定义：

# [ T_{\rm air}

\frac{
\max_j\sum_{i\ne j}\tau_{ij}
}{
\rho_{\rm target}
}.
]

也就是说，(\rho_{\rm target}) 是按**full-mesh always-report load**归一化出来的。

但是现在部署系统已经不是 full mesh。

它是：

[
\boxed{\text{owner-directed evidence plane}}
]

即每个 sensing UAV 的 token 只去目标 owner。

假设近似均衡分配，每周期每个 target 获得约：

[
K/Q
]

架 UAV 服务。

于是 owner-directed receiver 的实际 offered load 约为：

[
L_{\rm owner}
\approx
\frac KQ\tau.
]

而 full-mesh 基准为：

[
L_{\rm mesh}\approx(K-1)\tau.
]

所以相同 `rho_target` 下真正作用在当前算法上的有效拥塞大约是：

[
\rho_{\rm eff}
\approx
\rho_{\rm target}
\frac{K/Q}{K-1}.
]

你的两个 scale 恰好都有：

[
\frac KQ=2.
]

因此：

### ((8,4))

[
\rho_{\rm eff}
\approx
\rho_{\rm target}\frac27
\approx0.286\rho_{\rm target}.
]

### ((16,8))

[
\rho_{\rm eff}
\approx
\rho_{\rm target}\frac2{15}
\approx0.133\rho_{\rm target}.
]

所以在相同的 (\rho_{\rm target}) 下：

[
\boxed{
(16,8)\text{ 的 owner-directed 网络实际上获得了大约两倍宽松的相对 airtime budget。}
}
]

这就很容易解释现在的结果：

- ((8,4))：receiver capacity 相对更容易 binding；
- (\lambda) 有价值；
- density admission 有价值。

而：

- ((16,8))：capacity constraint 大量 slack；
- (\lambda) 不但没必要，还会错误抑制高价值 evidence；
- B0 反而更好。

这比“scale effect”更符合 KKT。

# 六、真正应该研究的是 capacity-binding transition，而不是 K/Q scale transition

这里反而出现了一个更漂亮的理论收敛点。

receiver constraint 是：

# [ \rho_j(x)

\frac{
\sum_{i,q:o(q)=j,a}
\tau_{ij}x_{iqa}
}{
T_{\rm air}
}
\le1.
]

其对偶变量是：

[
\lambda_j\ge0.
]

KKT complementary slackness 给出：

[
\boxed{
\lambda_j^\star
\big(\rho_j^\star-1\big)=0.
}
]

所以：

### capacity slack

[
\rho_j^\star<1
\Rightarrow
\lambda_j^\star=0.
]

这正对应 B0-lite。

### capacity binding

[
\rho_j^\star\approx1
]

或者 offered load (>1)，此时：

[
\lambda_j^\star>0
]

才有理论必要。

因此你现在看到的现象更适合被重新解释成：

[
\boxed{
\textbf{Receiver-capacity regime transition}
}
]

而不是：

[
\text{scale-dependent algorithm}.
]

这比硬写“8/4 用 CA、16/8 用 lite”理论上强很多。
