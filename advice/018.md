# 二、但当前 P5-A 的 CI 实际上没有严格对应表里的 (J)

这是我认为目前最需要修的代码问题。

正式报告的 pooled worst-target delay 是：

# [ J

\max_q
\frac{\sum_b S_{bq}}
{\sum_b N_{bq}},
]

其中 (S_{bq}) 是 block (b) 内 target (q) 的 H1 delay sum，(N_{bq}) 是对应 H1 个数。

代码确实这样计算总的 `J`。

但是 bootstrap 不是对这个量做的。

当前每个 block 先算：

# [ J_b

\max_q
\frac{S_{bq}}
{N_{bq}},
]

然后：

# [ \Delta_b

## J_b^{\rm prev}

J_b^{\rm cur},
]

最后对：

[
{\Delta_b}_{b=1}^8
]

bootstrap。

所以现在 CI 对应的是：

## [ \frac1B\sum_b \left[ \max_q\bar T^{prev}_{bq}

\max_q\bar T^{cur}_{bq}
\right],
]

而报告的主指标对应：

## [ \max_q \frac{\sum_bS^{prev}*{bq}}{\sum_bN*{bq}}

\max_q
\frac{\sum_bS^{cur}*{bq}}{\sum_bN*{bq}}.
]

一般有：

[
\boxed{
E[\max_q X_q]
\neq
\max_qE[X_q]
}
]

所以它们不是同一个 estimand。

当前数值非常接近，因此**不会推翻 Dπ 主导这个方向**，但作为正式统计证书不够干净。

### 正确修法

每个 block 保存：

```text
n_h1[b,q]
sum_h1_delay[b,q]
```

bootstrap 时抽 block index (b^*)，然后每次重新计算：

# [ J^{*(r)}

\max_q
\frac{
\sum_{b\in \mathcal B_r^*}S_{bq}
}{
\sum_{b\in \mathcal B_r^*}N_{bq}
}.
]

最终：

# [ \Delta^{*(r)}

## J_{\rm prev}^{*(r)}

J_{\rm cur}^{*(r)}.
]

这样 CI 和表里的 (J) 就是同一个统计量。

我把这个定为：

[
\boxed{\textbf{P1 必修}}
]

不需要改 scheduler，只改 runner/statistics。

# 四、“Dπ 占总收益 84%”建议立即降级措辞

当前：

数学没错。

因为：

[

也就是说正向机制先产生了较大收益，然后 λ 又把其中一部分吃掉了。

如果只看所有正增量：

+
\Delta_\pi^+
+
\Delta_{\rm adm}^+,

Dπ 大概只占：

[
\sim58%.
]

所以：

[
84%
]

其实是：

> **该 sequential increment 相对于最终 net A→C gain 的比例**

而不是：

> causal contribution share。

建议字段直接改名：

```text
ratio_to_net_A_to_C_gain
```

论文则写：

> Dπ is the largest positive sequential increment in the registered ladder; its increment equals about 84% of the final net A→C delay improvement.

换一个加入顺序，各 incremental contribution 会改变。

# 五、比 CI 更重要：当前 frozen-point delay 有一个“错误率交换”隐患

这是目前最需要认真对待的概念问题。

P5-A 的主要指标是：

[
E[T_q\mid H_1].
]

但是在代码中，只要 target 停止，不论它是在：

[
L_q\ge A_q
]

正确判 (H_1)，

还是：

[
L_q\le B_q
]

错误判 (H_0)，

`delays[r,q]` 都记录实际停止时间。

于是理论上存在：

[
\boxed{
\text{算法更早做出错误的 }H_0
\Rightarrow
E[T|H_1]\text{ 反而更小}
}
]

也就是说：

> lower stopping delay

不必然等于：

> faster useful evidence accumulation。

你现在 P5-A 五个 arm 的 QoS 全部是：

```text
UNCERTAIN
```

“UNCERTAIN”不是 FAIL，但也意味着：

[
\text{当前 artifact 没有证明各 arm 的 delay gain
不是通过更高 MD 换来的。}
]

而 runner 本来已经累加了：

```text
n_H0, n_H1, n_FA, n_MD
```

却最终只返回了：

```python
{"J", "block_J", "qos"}
```

这部分信息被丢掉了。

### 我建议不马上做 matched-QoS 五臂大实验

先做一个轻量 P5-A.1：

同时输出每个 arm：

[
P_{\rm FA,q},\quad
P_{\rm MD,q},
]

CS bounds，以及一个 error-aware delay：

# [ \boxed{ T_q^{risk}

\begin{cases}
T_q,&\hat H_q=H_1,\
T_{\max},&\hat H_q=H_0\text{ under }H_1.
\end{cases}}
]

于是：

# [ J^{risk}

\max_qE[T_q^{risk}\mid H_1].
]

如果：

[
\Delta_\pi
]

在普通 delay 和 risk-adjusted delay 上仍然都是最大正增益，并且 MD 没明显恶化，那么“task coordination 是主导机制”就非常硬了。

否则就要转 matched-QoS ladder。

# 十、我不建议现在继续调 (\mu_c) 把 λ“救回来”

那会重新进入参数打补丁。

正确做法是做一个 **λ-retention gate**。

比较：

[
B0
]

和：

[
C
]

在独立 geometry 上的四个维度：

[
J,\qquad
P_{\rm FA/MD},
\qquad
\text{offered/admitted airtime},
\qquad
\text{capacity drops / control bits}.
]

如果发现 B0：

- QoS 不差；
- pathwise capacity 当然仍满足；
- delay 更低；
- communication waste 没明显恶化；
- 还少了 (K b_\lambda) control bits；

那么：

[
\boxed{
\textbf{直接把 λ 从主算法删除。}
}
]

然后 λ 只作为：

> optional congestion-shaping extension.

这会让论文**更短、更漂亮、更容易解释，而且规模扩展更好**。

如果相反，λ 虽然损失一些 delay，但显著减少：

- offer traffic；
- dropped evidence；
- sensing/communication energy；
- 高负载下 instability；

那么才保留，并明确称为：

> delay–communication efficiency tradeoff mechanism.

这比现在笼统说“capacity steer”更有科学意义。
