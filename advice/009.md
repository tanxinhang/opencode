# 一、首先发现的 5 个 P0

## P0-1：QoS `UNCERTAIN` 会遮蔽后面的 certified FAIL

当前：

```python
for qq in range(q):
    ...
    if fa_lo > alpha or md_lo > beta:
        return "FAIL"

    if fa_hi > alpha or md_hi > beta:
        return "UNCERTAIN"
```

这意味着：

```text
target 0 = UNCERTAIN
target 1 = definitely FAIL
```

函数在 target 0 就已经返回 `UNCERTAIN`，target 1 根本不会检查。

这和函数自己定义的

[
\exists q:\mathrm{LCB}(P_{\rm err,q})>p_{\max}
\Longrightarrow \mathrm{FAIL}
]

不一致。

正确实现应该是先扫描全部目标：

```python
has_uncertain = False

for q:
    if LCB_FA > alpha or LCB_MD > beta:
        return "FAIL"

    if UCB_FA > alpha or UCB_MD > beta:
        has_uncertain = True

return "UNCERTAIN" if has_uncertain else "PASS"
```

测试里也没有覆盖这个顺序问题；甚至：

```python
assert status in ("UNCERTAIN", "PASS", "FAIL")
```

实际上是一个永远通过的断言，并没有测试任何逻辑。

# 二、P0-2：P3.4 把 `UNCERTAIN` 当成了 “QoS OK”

当前 Gate：

```python
qos_all_ok = all(
    (r["ca_qos"] != "FAIL") for r in scen_rows)
```

随后：

```python
"ca_qos_ok": qos_all_ok
```

也就是说：

```text
PASS      → OK
UNCERTAIN → OK   ← 错误
FAIL      → not OK
```

但 P3.4 自己写的是：

> congested: ≥5% worst-delay win **and certified QoS**

“certified QoS”只能对应 **PASS**，不是 “not FAIL”。

而正式结果已经把这个 bug 暴露出来了：

- 绝大多数 `ca_qos = UNCERTAIN`
- 只有一个 congested geometry 是 PASS
- 最终却输出 `ca_qos_ok = true`

应该改为：

```python
qos_all_pass = all(
    r["ca_qos"] == "PASS"
    for r in scen_rows
)
```

或者更合理：

```text
performance gate
+
QoS certification gate
+
physical-capacity gate
```

三个 Gate 独立输出，不再压缩成一个布尔变量。

当前 `adopt_ca=False` 是因为 12% regression 和 3.3% gain 没过，所以最终冻结 FRIDS-v2 的决策没有被这个 bug 改写。

但是如果未来性能超过 5%，现在的代码**可能在 QoS 全部 UNCERTAIN 的情况下错误 adopt CA**。

这是必须修的。

# 三、P0-3：CA-FRIDS 的 Monte Carlo run 之间存在状态泄漏

这个问题非常关键。

代码：

```python
load_smooth = load0 * max(t_air, 1e-30)

for r in range(n_runs):
    ...
    lam = ...
    for t:
        ...
        load_smooth = 0.8 * load_now + 0.2 * load_smooth
```

`load_smooth` 在 Monte Carlo run 循环**外部初始化**。

所以：

# [ \bar L^{(r+1)}_0

\bar L^{(r)}_{\rm final}.
]

换句话说：

> 第 301 个 Monte Carlo realization 的初始状态依赖第 300 个 realization。

这有两个后果。

第一，CA 性能本身被污染，因为每个 run 的 airtime dual transient 不一样。

第二，更严重的是，你后面对

[
N_{\rm FA},N_{\rm MD}
]

使用 binomial Clopper–Pearson interval，其基本采样模型是独立 Bernoulli trials。

现在 run 间存在 algorithmic state coupling，严格来说不再满足这一解释。

应该变成：

```python
for r in range(n_runs):
    load_smooth = load0 * t_air
    lam = ...
```

更进一步，我建议连 RNG 也改成：

```python
rng_r = np.random.default_rng([seed, r])
```

而不是让所有 run 共用一条长 RNG stream。

这样：

- episode 独立；
- 单个 episode 可复现；
- CRN A/B 比较更容易实现；
- QoS 统计假设更干净。

# 四、P0-4：本地 owner sensing 被错误收取通信 airtime price

CA action 的成本是：

# [ c_{iqa}

\frac{b_{\rm tok}}{R_{i,o(q)}T_{\rm air}}.
]

现在 `_g_and_c_actions()` 对所有 (i,q) 都这么算。

但后面的真实执行明确写着：

```python
if owner_of[qq] == uav:
    L[uav, qq] += llr_obs
```

并且通信阶段：

```python
if uav == owner:
    S[qq] += obs_iplus[uav]
    continue
```

即：

> owner 自己产生的 sensing evidence 是本地证据，不产生 U2U receive airtime。

所以理论上必须有：

[
c_{iqa}=0,\qquad i=o(q).
]

否则当前 CA score

# [ J^{CA}_{iqa}

\pi_qg_{iqa}
-\lambda_{o(q)}c_{iqa}

会错误处罚本地 sensing。

正确写法最简单：

```python
if i == owner:
    c_air = 0.0
else:
    c_air = airtime["tau"][i, owner] / t_air
```

而不是重新用 `rate` 算。

事实上 `build_airtime_model()` 已经把：

```python
np.fill_diagonal(tau, 0.0)
```

处理好了。

直接使用 `tau` 会更一致。

# 五、P0-5：CA 和 FRIDS-v2 的拥塞比较不是同一种物理 capacity model

这是当前 P3.4 最大的实验公平性问题。

### FRIDS-v2 congested baseline

使用：

```python
rx_cap_tokens
```

执行的是：

> Bernoulli physical offers
> → receiver hard admission
> → pathwise token capacity

即：

[
N_j(t)\le \lceil C_j\rceil
]

是 pathwise 保证。

------

### CA-FRIDS

却是：

# [ p_{\rm deliver}

s_{ij}
\min\left(1,\frac{T_{\rm air}}{L_j}\right).
]

即 overload 后对 token 做 probabilistic thinning。

它只是在平均意义上抑制接收负荷，并没有保证：

[
\sum_i \tau_{ij}z_{ij}(t)
\le T_{\rm air}
]

逐周期成立。

正式结果本身也说明这一点：

```text
rho_full     = 1.8
CA max load  ≈ 1.63–1.68
budget feasible fraction ≈ 0.48–0.51
```

所以目前比较实际上是：

```text
FRIDS-v2 : hard capacity
CA       : soft probabilistic overflow
```

这不是同一个 MAC/receiver feasibility model。

### 建议

统一为：

[
\boxed{
\text{Dual price steering}
+
\text{hard receiver admission}
}
]

两层结构：

```text
CA price:
尽量让发送者提前避开拥塞

Hard token bucket:
最终保证物理 capacity pathwise 可行
```

λ 是**优化机制**；

hard admission 是**物理可行性保险丝**。

不能用 λ 替代 MAC feasibility。

# 六、真正导致 12% regression 的理论核心：当前 CA 并不是它声称的 exact dual

这个比参数问题重要得多。

当前声明的 primal 是：

[
\begin{aligned}
\max_{x,z}\quad &z\
\text{s.t.}\quad
&G_q(x)\ge z,\quad \forall q,\
&A_i(x)\le1,\
&C_j(x)\le1.
\end{aligned}
]

引入 target dual (y_q)：

# [ \mathcal L

z+
\sum_qy_q(G_q-z)
-\sum_j\lambda_j(C_j-1).
]

关于 (z)：

# [ \mathcal L

z\left(1-\sum_qy_q\right)
+
\sum_qy_qG_q
-\sum_j\lambda_jC_j+\cdots
]

为了 dual function 有界，必须：

[
\boxed{\sum_qy_q=1}.
]

也就是 **全局 target simplex**。

FRIDS-v2 正是围绕这个结构构建的。

------

但 CA-FRIDS 当前实现是：

```python
for uav in range(k):
    owned = [...]
    ...
    y_new[owned] /= sum(y_new[owned])
```

也就是：

[
\sum_{q:o(q)=j}y_q=1
]

**每个 owner 各自一套 simplex。**

如果有 (M) 个 active owners：

[
\sum_qy_q=M,
]

而不是 1。

更糟糕的是，如果：

```text
每个 owner 正好只负责 1 个 target
```

则必然：

[
y_q\equiv1.
]

于是 mirror descent 完全退化。

当前代码自己其实已经观察到了：

> single-target owner keeps y=1

这就是现在 12% uncongested regression 最合理的理论解释。

所以我不认为：

> “CA-FRIDS 的联合 capacity 思路失败了。”

更准确的是：

> **“当前 owner-local simplex approximation 破坏了原 max-min dual structure，因此 CA-v0 失败。”**

这两句话在论文价值上完全不同。

# 七、我建议的下一版：Simplex-Preserving Dual-Bus CA-FRIDS

不要回到 full-mesh belief。

只恢复一个**全局 dual normalizer**。

每个 target owner 维护一个 log-weight：

[
\theta_q(t).
]

定义：

[
w_q(t)=e^{\theta_q(t)}.
]

只需要全网计算：

[
Z(t)=\sum_{q\in\mathcal U(t)}w_q(t).
]

于是：

[
\boxed{
y_q(t)=\frac{w_q(t)}{Z(t)}
}
]

严格保证：

[
y(t)\in\Delta_Q.
]

### Mirror update

normalized service：

# [ r_q(t)

\frac{S_q(t)}
{D_q(t)+\epsilon}.
]

可以直接：

# [ w_q(t+1)

w_q(t)e^{-\mu r_q(t)}.
]

然后全局归一化。

注意并不需要显式计算原来的 global `rbar`。

因为：

[
y_q^+
\propto
y_qe^{\mu(\bar r-r_q)}
]

而公共因子 (e^{\mu\bar r}) 在 simplex normalization 中自动消失。

因此：

# [ \boxed{ y_q^+

\frac{y_qe^{-\mu r_q}}
{\sum_p y_pe^{-\mu r_p}}
}
]

即可。

这仍然是标准 entropic mirror descent。

[
I^+_{iqa}=D(P_1\Vert P_0),

# [ p_q(t)

D_q^+=A_q-L_q,

\frac{I^+*{iqa}}{D_q^++\epsilon}

# 十三、Exact min-cut 方向是正确的，但还能做一次复杂度升级

你当前 closure construction 对 UAV (i) 的每个 level：

```python
for qq:
    if g[i, qq] >= gamma:
        target -> auxiliary
```

最坏需要：

[
O(KQ^2)
]

条 closure edges。

可以利用 level 的嵌套结构压缩成 **chain closure**。

对 UAV (i)：

[
0<\gamma_{i1}<\gamma_{i2}<\cdots<\gamma_{iL}.
]

建立：

[
v_{i,L}\rightarrow v_{i,L-1}
\rightarrow\cdots
\rightarrow v_{i,1}
]

INF edges。

target (q) 只连到：

[
v_{i,\ell(q)},
\quad
\ell(q)=\max{\ell:g_{iq}\ge\gamma_{i\ell}}.
]

激活最高 level 后，closure chain 自动激活全部低 level。

于是 edge 数从：

[
O(KQ^2)
]

降到：

[
\boxed{O(KQ)}.
]

而 min-cut 值完全不变。

建议增加测试：

```text
dense closure
vs
chain closure
vs
bruteforce
```

三者逐点一致。

对于未来：

```text
K = 32/64
Q = 64/128
```

这个优化会非常重要。

# 十四、还有一个隐藏的 hard-admission 公平性 bug

FRIDS-v2 fractional admission：

```python
extra = [u for u in offered if u not in keep]
keep = keep + [extra[0]]
```

因为 `offered` 是 UAV index 顺序进入：

```text
0,1,2,...
```

所以 fractional extra slot 偏向低 index UAV。

正确应该是：

```python
extra_uav = rng.choice(extra)
```

这样才是 exchangeable admission。

否则在：

- fixed owner；
- heterogeneous target quality；
- sender index 与 geometry 恰好相关；

的情况下会产生很隐蔽的 fairness bias。
